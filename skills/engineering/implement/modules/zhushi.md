# 代码注释规则

> 本模块只管工程判断：何时写注释、写什么、何时禁止写、标记类注释怎么写、旧注释怎么处理。注释语言遵循主文件的规定。

**注释只写代码本身读不出的信息；复述代码的注释一律不写。** 注释面向的读者是「掌握所用语言惯用法、但不了解本项目历史的维护者」：他们看得懂惯用法，看不懂你的决策过程，注释就是写给他们的。判断依据是信息能否从代码本身读出，不是代码「清不清楚」：刚写完的代码在作者眼里永远是清楚的，这个判断不可靠。

写代码时不为注释停顿。全量测试通过后、进入评审前，对本次新增和修改的逻辑回扫一遍，命中下列任何一类必须补注释。

## 何时必须写

- **为什么这么做、为什么不选更直觉的做法。** 凡一段代码会让读者问「为什么不直接 X」，就需要一条注释回答这个问题；绕弯、看似多余的步骤、没有名字的阈值，都是这个信号。
- **外部约束的来源。** 协议条款、上游 bug、平台怪癖、合规要求：这些约束从代码形状上推不出来。
- **刻意做的简化或捷径。** 标出它的上限和升级路径，免得后来的人分不清是漏了还是故意：

    ```cpp
    // 简化：先用全局锁，所有账号共用一把；高并发下会串行、成为瓶颈，吞吐吃紧再换按账号加锁。
    ```

- **代码里看不出来的来历。** 魔法数字为什么是这个值、为什么这里重试三次、为什么顺序不能换。
- **公共接口的契约信息。** 调用方必须知道、但签名和类型读不出的内容：返回值的歧义语义（空列表是没查到还是查全了）、副作用（网络、文件、全局状态）、参数约束和前置条件。写进 docstring，让调用方不读实现就能正确使用；简单 getter 和直白单行不需要。
- **声明处的精度信息。** 单位（毫秒还是秒）、边界是否含端点、null 或零值的特殊含义、资源所有权归谁、不变量：名字和类型给不出的精确语义。

## 何时禁止写

- 复述代码内容的注释。
- 解释语法本身的教程式注释。判据：删掉它，损失的是这个项目的信息，还是任何语言教程都有的信息：

    ```rust
    // ❌ 教程式：clone() 会深拷贝，避免所有权转移
    // ✅ 决策式：这里 clone 一份给缓存，原值后面还要用，不能交出所有权
    ```

- 给命名自解释、逻辑直白的代码补的格式性注释。
- 为了「显得规范」而写的模板化 docstring。docstring 里有契约信息就写，没有就不写，不为格式而填。
    ```cpp
    // ❌ 只重复代码，无额外信息
    // 调用函数清理临时目录。
    ScheduleTempDirectoryCleanup(tempPath);
    
    // ✅ 提供了代码里没有的信息
    // Windows Installer 在卸载阶段可能仍持有文件句柄，这里延迟删除临时目录。
    ScheduleTempDirectoryCleanup(tempPath);
    ```

## 用户不熟时

用户声明对所用语言不熟时，语言构造的讲解放进交付说明，不塞进代码注释：交付时把本次改动用到的非基础构造（新惯用法、关键 trait、宏）讲清楚。代码注释仍然只装项目知识。

## 写法细则

- **写具体，不写笼统。**「带 1 秒退避重试 3 次」，不是「处理了重试」。
- **引用常量名，不复述值。** 行为由常量控制时，注释写常量名，不重复它的值：改常量时不用同步两处。单位换算是例外（`1048576 // 1MB` 增加清晰度，不算重复）。
- **会过期的注释标移除条件。** workaround、版本特定代码注明什么条件下删除，如「Safari 14 停止支持后移除」。

## 标记类注释

TODO、HACK、FIXME 只用于记录当前任务范围外、但值得留痕的事，必须可追踪：写清被什么阻塞（issue 编号）、何时可移除。禁止用 TODO 占位代替实现。

```text
// TODO: 抽成共享工具，等移动端 API 对齐（MOBILE-123）
// HACK: 绕过 Safari 14 的 flexbox bug，停止支持该版本后删除
```

## 自检与同步

- **反向自检**：删掉这条注释，损失的必须是这个项目的信息；损失的是语言教程都有的信息，或者什么都不损失，就删。
- **旧注释同步**：改动使旧注释失效时，同步更新或删除该注释。留下「注释说 A、代码做 B」比没有注释更糟。

# 向导

**向导（wizard）**是一个 bash 脚本，带着用户一步步走完一套手动流程。这类流程手动做一遍很繁琐，每次向 AI 重新解释一遍也很繁琐。向导的意义是可以替用户打开各种 URL，并提示用户应该点什么地方、复制什么信息，再引导用户把AI需要用到的信息，写到该去的位置（`.env`、GitHub secrets）。典型场景是配置第三方服务、执行一次性迁移，或完成换服务商、换数据库这类整体切换。

[template.sh](scripts/template.sh) 已经把顺手的交互体验都做好。**你只负责划定流程范围、编写各个阶段**：模板里 `STAGES` 标记之上的库在每个向导里一字不差，你的全部改动都落在标记之下。

向导默认是一次性的：跑一次就完事，存到临时位置（scratch）或 `scripts/` 下，活干完就删。只有用户想把它留成仓库里可重复使用的设置流程时，才提交。

## 流程

### 1. 划定流程范围

弄清需要用户手动执行的每个步骤，以及过程中要捕获的每个值。先读仓库，读不到答案再问用户：

- 设置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每处 `secrets.*` / `vars.*` 引用都是一个向导必须产出的值）。
- 迁移或切换类：当前状态、目标状态，以及两者之间的不可逆动作。

然后把排好序的阶段清单、每个阶段产出的值摆给用户确认：用户可以增加、删除或重排。

**完成标准：**每个阶段都按顺序命名，并且对每个捕获的值你都答得上来：(a) 人从哪里拿到它；(b) 它写到哪里（`.env`、GitHub secret、两者都写，或都不写；有些阶段是纯动作）；(c) 它是机密（隐藏输入）还是公开的。

### 2. 映射每个阶段的路径

给每个阶段写出用户要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、要填进哪个变量，例如 "Dashboard → Developers → API keys → Reveal test key → copy"。凡是没把握的界面或命令，直说，问用户或查文档；只写核实过的步骤。

**完成标准：**每个阶段都有具体到陌生人照着也能做下去的指引。

### 3. 编写向导

把 `scripts/template.sh` 复制到目标路径。把示例阶段替换成每个步骤一个 `stage`，按依赖顺序排列，`TOTAL_STAGES` 设为阶段数。库助手各司其职：`banner`/`finish` 开场与收尾摘要；`stage` 清屏并显示阶段进度；`say`/`step`/`note`/`warn` 输出指令与提示行；`open_url` 跨平台打开浏览器（含 WSL）；`ask`/`ask_secret` 捕获值，机密用 `ask_secret` 隐藏输入；`write_env` 幂等写入 `.env`；`set_secret`/`set_var` 写 GitHub secret/variable；`pause`/`confirm` 确认关卡。

守住模板立下的标准：先打开 URL，再向用户要值；凡是机密都用 `ask_secret`；每个要持久化的值都 `write_env`；只把 CI 真正需要的值交给 `set_secret`；任何不可逆动作之前先 `confirm`。每个 `stage` 都会清屏，只显示当前步骤，所以一个阶段只干一件事，用户需要的信息就不会滚出屏幕。

### 4. 验证并交接

- `bash -n <script>`；有 `shellcheck` 就跑一遍。
- `chmod +x <script>`。
- 验证靠静态走查：第 1 步列出的每个值都捕获到了、落点和第 1 步说的一致，每个 `set_secret` 的名字都和 CI 里的 `secrets.*` 引用对得上。不要自己端到端运行，脚本会弹出浏览器、卡在等用户输入上。
- 告诉用户怎么运行。如果这套流程以后还会重复跑，就把它提交进仓库，并在 README 里加上链接，让下一个人直接跑脚本，而不是来问 AI。

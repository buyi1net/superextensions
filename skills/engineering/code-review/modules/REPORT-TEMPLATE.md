# 最终报告结构模板

代码评审最终报告的结构模板,配合主 SKILL.md 第五步使用.按实际检查结果填写,没有对应内容的占位项可以删去.

```markdown
# 代码评审报告

## Spec (规格说明)

> 依据来源: [Issue / 规格文件 / 会话上下文 / 无可用规格]

- [未满足 / 偏差 / 超范围]: <简述>
  - **规格要求**: 「<引用原文>」
  - **实际现状**: <实际实现情况及对应位置>
  - **建议**: <修改建议>

**核查结论**: <实际检查范围与结论;未完成或未评审的部分及原因>

---

## Standards (编码规范)

> 依据来源: [项目规范 / codebase-design / 四组检查规则]

### 本次需修正的问题

- **[检查组 / 规则 / 坏味道名称]** `文件:行号`
  - **问题与证据**: <明确违反的规范,或设计判断及其实际影响;附证据和与本次改动的关系>
  - **修改建议**: <具体的重构或修复方向>

### 核查结论

- **设计与源码组织**: <设计,结构与体量的已查范围和实际结论;未完成或不适用项及原因>
- **死代码**: <残留与误删的已查范围和实际结论;未完成或不适用项及原因>
- **重复逻辑与复用**: <重复实现和不当复用的已查范围和实际结论;未完成或不适用项及原因>
- **编码与项目规范**: <本次适用规范的已查范围和实际结论;未完成或不适用项及原因>

### 待核实或后续事项

- <与本次改动无关的历史遗留,或证据尚不充分的建议>

---

## 结论

* **Spec 轴**: <实际评审情况;已确认的问题数和最严重发现(如有)>
* **Standards 轴**: <实际评审情况;已确认的问题数和最严重发现(如有)>
```

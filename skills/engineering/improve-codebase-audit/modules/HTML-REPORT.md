# HTML 报告规范

生成报告时读取本文件。`SKILL.md` 规定怎么检查，本文件只规定报告写什么、页面怎么呈现和交付前怎么验收；[report.html](../assets/report.html) 是可以直接复制的参考实现。参考实现与本文件不一致时，以本文件为准。

## 报告内容

报告列出本轮已经合并后的全部独立发现，说明现状、影响、证据、待确认条件和处理方向。它是时点快照，不是整改工单，也不提前做接口设计、工时估算或技术选型。

顶层数据包含：

| 字段 | 要求 |
| --- | --- |
| `project` | 项目名称。 |
| `date` | 报告日期。 |
| `scope` | 实际检查范围、分片方式、抽样依据、版本和未检查区域。零发现也必须写。 |
| `note` | 必要说明，例如演示数据、工作树状态或无法复核的限制；没有就写空字符串。 |
| `candidates` | 发现数组，可以为空。 |

每条发现包含：

| 字段 | 要求 |
| --- | --- |
| `id`, `subsystem` | 稳定且唯一的编号（如 `A01`）和项目已有的子系统或业务域。 |
| `title` | 一句话点出问题和位置。 |
| `criterion` | 本条命中的体检判据，取自六个短名：组织与体量、重复与复用、死代码与遗留、测试与工程入口、声明与规则漂移、命名与注释；短名打头，可接「·」加一句具体化。只写判据，不写内部来源或工作过程。 |
| `problem` | 一句说清现状偏离和实际影响。 |
| `priority` | `high`、`medium`、`low` 三选一。 |
| `reason` | 严重程度为什么是这一档。 |
| `evidence` | 非空数组；每项写仓库相对路径、符号或行号和可复核现象。 |
| `uncertainties` | 尚未验证的条件；没有就用空数组。 |
| `proposal` | 处理方向，写顺手整理、先补测试再动或专项立项等路径，不写立即返工令。 |
| `benefits` | 2 至 3 条处理完成后的具体改善。 |
| `impact` | 受影响的模块、调用方、入口和契约。 |
| `files` | 仓库相对路径数组，完整列出证据涉及的文件。 |
| `related` | `{id, relation, note}` 数组；`relation` 只取「前置」「替代」「关联」。无关系用空数组，不自指、不重复、不指向不存在的编号。 |
| `diagrams.before`, `diagrams.after` | 现状图和有限的处理方向图，各有 `kind`、`title`、`caption` 和非空 `legend`（每项含 `label` 与 `box`/`line`/`circle` 图形）；`kind` 只取 `flow` 或 `svg`，并按图种提供 `nodes` 或 `source`，缺图例的数据不通过模板校验。 |

目录只放编号、标题、严重程度和一条改善摘要。详情按判据、问题与现状、处理建议、严重程度依据、前后图、处理后的改善、处理波及范围、已见证据、待确认、涉及文件、相关发现的顺序展开。

三档严重程度的名称、数量和一句话含义必须同时显示；含义与 [SKILL.md](../SKILL.md) 第五步的定义保持一致。

## 页面布局和交互

采用“固定信息栏 + 左侧目录与筛选 + 右侧详情”的单页布局。页面贴满窗口，不加外层卡片；报告信息浮层展示完整项目名、日期、范围、说明和严重程度分布。

- 目录按子系统分组；筛选包含子系统、严重程度和搜索，三者取交集。搜索覆盖编号、子系统、标题、问题、处理建议和文件路径，多个空格分开的词必须全部命中。
- 筛选即时生效并保留输入焦点；当前项仍匹配就保留，否则选结果第一项；零结果清掉旧详情并给出清空入口；清空恢复全部发现。
- 每条发现有稳定片段链接（如 `#A01`）。目录、相关项和上一项/下一项都按当前筛选结果导航；无效编号给出明确提示。
- 桌面目录独立滚动、详情使用页面滚动；窄屏目录在上、详情在下，发现列表限高并可独立滚动；矮窗口不得把筛选控件滚出视野。
- 报告信息按钮支持键盘操作，点击外部、焦点移出、窗口失焦或按 Esc 时收起；Esc 后焦点回到按钮。筛选、目录、导航和图示链接均可键盘访问。

样式沿用参考实现的浅底、白色内容区、细边框、绿色选中态和文字徽章。颜色只辅助表达，严重程度必须有文字；正文约 16px、行高约 1.7，目录约 290–320px，详情最大宽度约 1280px。

## 图示

现状图在前，处理方向图在后。每张图都有标题、用一句话写出的图注和紧邻图例。并列关系不要画成执行顺序；只有真实调用或时序才用箭头表达先后。前后图保持方向、模块名称和颜色含义一致。

- 简单顺序关系用内联 HTML 节点和箭头。
- 依赖或时序使用内联 SVG；报告运行时不加载外部绘图库。
- 横截面、职责剖面和体量示意用带 `viewBox` 的 SVG；矩形面积只能表达概念，不能冒充代码量。
- 图中文字在最终显示尺寸下至少 14px；宽图只在图区域横向滚动，不撑宽整页。
- 图加载或语法失败时，保留图注、证据、正文和筛选能力，并在交付前修好。异步渲染不能让旧发现的图覆盖当前详情。

## 文件与数据安全

报告是单个 HTML 文件，CSS、JavaScript、数据和基础交互都内联，本地直接打开即可使用。项目文字按文本展示，不能执行其中的 HTML 或脚本；链接只允许 `http:`、`https:`、`file:`（无主机名）、相对路径或页内片段。

报告数据必须先由脚本正常序列化，再把 JSON 文本中的 `<` 替换为单反斜杠形式的 `\u003c`，防止项目文字中的 `</script>` 提前结束数据区。页面数据解析失败时给出明确错误，不显示空白页；禁用 JavaScript 时说明需要启用交互。

## 交付验收

逐项验收真实报告：

1. 数据数量、严重程度分布、编号、字段完整性、目录和相关链接与内容一致；零发现时仍能查看范围。
2. 子系统、严重程度、多词搜索和清空筛选结果正确；选中项、详情、地址和焦点同步。
3. 目录、相关项、上一项/下一项、直接片段链接、刷新、前进后退和无效编号行为正确。
4. 报告信息浮层的内部点击、外部点击、焦点移出、失焦、Esc 和键盘焦点符合规则。
5. 宽屏、窄屏、矮窗口下顶栏、筛选、目录、详情、长路径和宽图都可访问，页面不被撑宽。
6. 每张图的文字、图例、方向和图注一致；快速切换不会串图；绘图库或图语法失败时有提示且正文可读。
7. 数据里含 `<`、`</script>`、长路径和特殊字符时，页面不截断、不执行、不报错。

修改模板实现时，另用少量、几十项和零发现的虚构数据覆盖适用交互；虚构数据必须明显标注，且不混入真实交付报告。

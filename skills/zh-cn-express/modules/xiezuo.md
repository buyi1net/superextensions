# 通用中文写作

> 本模块处理文档、报告、README、commit、稿件和社交内容等中文成稿，只补普通中文写作相对于主框架新增的制度。对话回复、翻译、代码注释、界面字符串和外语成稿分别走主文件指定的专门模块。

**必读配套：** 写完后完整执行 [去 AI 味检测表](./aiwei.md)。

## 文件语言与既有风格

- 修改已有中文文件时，沿用文件已经统一的语言、术语、标题层级和格式。目标文件以其它语言为主时，返回主入口按目标语言重新路由。
- 中文文档里的英文示例、信号词、引用和真实源码保持原样；教学示例中面向读者的说明用中文，代码注释交给代码注释模块处理。
- 英文专属规则标明“仅英文适用”，不把英文模板的标题和套话机械带进中文成稿。

## 信息组织

正文先给结论或目标，再给支撑它的事实和必要步骤；没有下一步就停，不补空话结尾。修饰词能换成事实就换，删掉会让读者误解、漏做或出错的信息必须保留。

## 中英混排

英文技术标识嵌入中文句子时，前后留空格；API、commit、PR 等已经自然进入中文技术语境的常用词不机械加空格。普通概念有稳定中文说法时直接用中文，代码标识和产品名不为中文化而改写。

```md
## 构建流程

使用 `cmake --build` 执行构建，输出目录为 `Support/Build/`。
```

不要写成半中半英的句子：

```text
Use `CreateProcessW` 启动子进程 and log `GetLastError()` when failed.
```

## 文件链接

当中文成稿要求读者打开另一个 Markdown 文件时，必须使用带目标路径的 Markdown 链接，不得只写反引号路径。相对链接以当前 Markdown 文件所在目录为基准解析，不以项目根、skill 根或 Agent 当前工作目录为基准。

标准形式：

```markdown
[同目录文件](./other.md)
[子目录文件](./modules/memory.md)
[上级目录文件](../SKILL.md)
```

链接文字应直接说明目标文件或用途，不写“点这里”等无法定位内容的文字。写完后按当前文件所在目录核对链接目标，确认路径前缀和文件位置都正确；发现目标不存在或层级关系不符合预期时，先修正链接，不把错误路径留给读者或后续 Agent。

以下内容不是当前 Markdown 文档中的跨文件导航，不机械改成链接：命令、配置、代码和其它需要保留原样的字面路径；外部机器、用户主目录或运行时项目中的文件；模板实例化后才会出现的文件；以及只是在正文中说明文件名的情况。这些内容继续使用反引号，并在确有歧义时补充它所属的上下文。

## 成稿质检

1. 删套话、重复解释和空洞修饰，保留事实、限制、代码、命令、路径、报错与安全步骤。
2. 完整执行 [去 AI 味检测表](./aiwei.md)，发现问题直接改稿，不向用户逐项汇报检查过程。
3. 从读者视角通读一遍；第一遍会卡住、回读或猜测的地方继续改。
4. 检查语言、术语、标题和格式是否跟随用户要求、项目规则与现有文件；没把握的断言留在成稿外说明。

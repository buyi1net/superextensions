# 外文译中文

> 本模块只补外文译中文相对于主框架新增的制度。中文译外语或按中文意图直接写外语见 [对外表达](./duiwai.md)。中文译文还要执行 [去 AI 味检测表](./aiwei.md)，但准确和保真高于风格清理，不得为去 AI 味删改原文信息、力度、情绪、强调或结构。

## Agent 与规则文档

翻译 skill、`AGENTS.md`、`CLAUDE.md`、system prompt、Agent 工作流或其它会影响执行行为的规则文件时，额外完整读取并执行 [Agent 与规则文档翻译](./fanyi-agent-wendang.md)。这类任务除了语言准确，还必须保持调用范围、规则力度、步骤、分支、停止条件和文件机制。

## 中文意译

意译不是翻得宽松，而是中文句子围着意思重新组织，不围着原文骨架填字。允许拆句、并句、换成语和调语序；不允许丢信息、加信息或改变强调程度。原文有情绪就保留情绪，原文委婉也不能译成强硬。

从英文翻中文时逐项检查这些欧化症状：

| 症状 | 表现 | 修正 |
|---|---|---|
| 名词化 | 进行了讨论、做出了让步 | 把名词还原成动词：讨论了、让步了 |
| 被动滥用 | 它被认为是、被用来做 | 真被动才留“被”，其余改主动 |
| 名词堆砌 | 长修饰语链压在名词前 | 拆短句，先说主体再补条件 |
| 硬搬“是……的” | 照抄 `It is...that` 的强调骨架 | 按中文自然语序重写 |
| 代词冗余 | 他、她、它、我们反复出现 | 上下文已指明时省略 |
| 连词堆砌 | 因此、然而、此外到处都是 | 逻辑已清楚时删掉 |
| 引导句直译 | 把英文式标题或引导语硬搬成中文 | 直接说读者要做什么 |

## 习语、比喻和多义词

习语、比喻和文化典故逐个选择：直接说含义、换成中文里效果相同的表达，或在中文读者能直接理解时保留原意象。判断标准是目标读者第一次读到是否需要猜。

译文不得为了生动自行增加原文没有的比喻。自造比喻连续两次解释不通，直接改成陈述。

多义词先按语境定含义再翻，例如：

| 原文语境 | 错译 | 合适译法 |
|---|---|---|
| prose（泛指行文） | 散文 | 正文、文字、行文 |
| bucket（目录分组） | 水桶 | 分组 |
| harness（运行环境） | 马具、驾驭 | 运行环境，必要时首现保留英文 |
| argument（函数参数） | 争论、论点 | 参数 |
| contract（接口约定） | 合同 | 约定、契约 |

## 译中术语

翻译前只锁真正影响理解或一致性的关键术语，不为常见、无歧义的词机械建立术语表。没把握时先查 [英中术语表](../glossaries/en-zh.md)；表里没有的按质检门“推测标注”处理。

社区约定俗成保留英文的术语，如 agent、skill、commit、token、prompt，跟随目标项目的既有惯例，不为中文整洁强行翻译。

## 长文与重要文档

长文分块时先锁全文术语和语气，再在标题或完整段落边界切分；各块共享同一套领域、术语和比喻判断。合并后检查术语同形、语调一致和块间衔接。

译文要出版、长期存档或会影响 Agent 执行时，在主框架的分层审校之外增加一次独立审校：审校者只诊断准确性、欧化表达、术语、比喻和流畅度，不直接修改；主执行者按问题清单修订，再通读全文。默认不为分析或审校单独创建文件，用户明确要求时再按项目治理确定位置。

## 翻译质检

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 占位符 | 忠实译文中的 `<xxx>` 等变量逐字保留；只有明确要求改编内容时才填充或解释 |
| 2 | 原样保留 | 源码、代码标识、命令、配置键、API、环境变量和版本号逐字核对；路径与 URL 默认保留，明确本地化后实际验证 |
| 3 | 术语同形 | 锁定的术语每次出现完全一致，同一概念没有多个名字 |
| 4 | 信息边界 | 不增删信息，因果、责任和强调程度不变；译者说明不混进正式译文 |
| 5 | 数字实体 | 数字、日期、单位、金额与原文核对，不做未要求的换算 |
| 6 | 推测标注 | 没把握的译法和查不到出处的定译放在成稿外的待复核清单；没有疑点时不输出该栏目 |

短句、单词和口语片段可以简化分析与审校过程，但保护内容、信息边界和实际疑点仍须核对。

# 跨会话记忆

> 本模块统一约束项目记忆、全局记忆、本地记忆文件和共享记忆 MCP 的读取与变更。无论记忆动作由用户、constitution 还是其它模块触发，都必须按本模块处理；其它规则中的“主动记忆”只表示主动提出候选，不授权直接写入。

## 基本边界

- 记忆是有则用之的辅助，不是开工门槛。没有已声明的记忆设施，也没有产生记忆候选时，正常完成任务，不为寻找、创建或读写记忆卡住。
- 记忆保存以后仍有用、但不能方便地从源码、Git、项目文档或规则入口重新取得的信息。规则和记忆分开：不得把 `AGENTS.md`、`CLAUDE.md` 或系统提示词当作记忆载体；确需把一条记忆升级成规则时，单独说明影响并取得用户明确批准。
- 密码、密钥、token、私钥、完整 `.env` 等敏感信息不得写入记忆。未经验证的判断不得冒充事实；用户明确要求保存待验证信息时，必须标明未确认状态。
- 项目专用事实、决定和偏好属于项目记忆；机器级配置、跨项目事实和长期通用偏好属于全局记忆。通用内容只写全局，项目特例只写项目，不重复保存；两者冲突时，当前项目内以项目特例为准，并向用户说明冲突。

## 读取

- 读取已有记忆不需要用户确认。先读入口或索引，再根据当前任务读取相关主题；禁止无差别加载全部项目记忆或全局记忆。
- 项目入口已登记记忆位置时，先读该入口，再读相关主题文件。文件型全局记忆同样先读入口或索引；MCP 等服务优先使用其索引、摘要或检索能力，只取当前任务需要的内容。
- 只使用当前环境或项目明确声明的记忆设施。Agent 安装目录、普通配置目录和系统提示词目录不因位于全局路径就自动成为全局记忆位置；只有环境明确声明的具体路径或服务才算记忆设施。
- 同类全局记忆存在多个位置时，核实每个位置的准确路径或服务名称及作用范围；当前任务只需读取相关位置，不把不同存储中的内容混成一个未经核对的结论。
- 当前用户指令、已验证事实与记忆冲突时，不照旧记忆继续执行；指出冲突并按最新确认结果处理。

## 记忆候选

判断一条信息是否值得长期保存，先问：下次忘记它，会不会导致重复踩坑、重复询问、违反已确认决定、选错方案，或者重新花时间验证。可能造成这些明确成本时，将它列为记忆候选；拿不准但有合理价值时也可以提出，并说明理由，不设置僵硬的准入清单。

信息能从其它地方查到，不等于绝对不能记。查找成本高、入口隐蔽或曾反复找错时，可以记录准确导航。一次性状态、当前进度、完整会话摘要和用完即弃的信息通常不提出长期保存。

Agent 主动发现候选时，不打断正在进行的工作；在任务自然停顿或结束时集中列出准备记录的内容、推荐归属、实际可写位置和理由，等用户决定。用户主动要求“记住这条”时立即处理。

## 写入授权与位置

- 新增、修改、删除、迁移和批量整理记忆都需要用户明确授权。用户已经给出具体内容和准确目标时，不重复询问；目标存在多个可能位置、用途不明、不可写、被占用或归属明显可疑时，列出事实和推荐后询问。
- 用户只说“写入项目记忆”或“写入全局记忆”，而该范围内有多个实际存储时，列出准确路径或服务名称让用户选择；只有一个已声明且可安全写入的位置时，直接使用。
- 项目信息无法安全写入项目记忆时，说明原因并保留为候选，不得擅自退回全局记忆。写入失败也不得偷偷更换位置。
- 获得授权前，先说明会创建或修改的准确位置。用户据此确认建立项目记忆后，该次授权可以同时覆盖创建记忆入口、相关主题文件以及在项目根入口登记稳定路由，不为同一组已披露的联动改动重复询问。

## 项目根与项目记忆

用户未明确指定项目目录时，按以下顺序确定项目根：

1. 使用当前环境明确提供的 workspace root。
2. 没有 workspace root 时，结合版本库根、根级 `AGENTS.md`、`README.md` 和项目清单文件判断；不得只因当前目录里有普通文件就认定为项目。
3. 磁盘根、文件系统根、操作系统目录、用户主目录、系统临时目录和 Agent 安装目录不算项目根。
4. 多个依据互相冲突或仍无法可靠判断时，询问用户，不得猜测。

项目已有明确记忆位置和组织方式时沿用现状；新建时默认使用项目根的 `.agents/memory/`：

- `README.md` 只说明记忆范围并索引主题文件，不堆放记忆正文。
- 记忆正文按实际主题写入独立文件，内容出现时才创建，不预建空文件或空目录。
- 根 `AGENTS.md` 只登记项目记忆入口及触发条件，不复制记忆正文；创建或修改入口时遵守项目的入口治理规则。

## 多 Agent 与并发写入

- 多 Agent 协作中只有能与用户交互的主 Agent 可以实际变更记忆。子 Agent 只向主 Agent 提交候选、证据和推荐位置，不直接写项目记忆、全局记忆或共享 MCP。
- 写入前重新读取目标，只做精准新增或修改，不拿旧内容整体覆盖。发现文件被占用、读取后又被修改、存在未合并变更，或者共享 MCP 的并发写入能力不明时，停止写入并向用户说明。
- 新信息与旧记忆冲突时，不追加成两条互相矛盾的结论。展示旧内容和新证据，提出更新、废弃或并存建议，等用户确认后处理。
- 写入完成后重新读取或查询目标，核对实际保存的内容和位置；没有验证成功就不得声称已经记住。

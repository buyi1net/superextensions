# 记忆系统

> 核心原则：能不写记忆就不写记忆。真要写入的话，写入前先分流；其他地方能承载的，就不进记忆。本模块统一约束记忆的读取与写入。

## 分流

分流时，按内容归属选择载体，优先顺序如下：

- 项目决策、设计取舍：写入 `ADR`（domain-modeling）。
- 术语、概念边界：写入 `GLOSSARY`（domain-modeling）。
- 任务进度、待办：写入工单（工程流）。
- 项目环境事实、踩坑：写入 docs 文档。文档有索引、同步和过时清理；记忆系统没有维护机制，过时了也没人清。
- 跨项目偏好、机器级事实：写入全局记忆（即本模块）。
- 以上都不匹配，并且只对当前项目成立、换个项目就不适用时，才考虑项目记忆（可选层，见“载体”）。

## 载体

记忆载体分全局和项目两类。全局指当前环境声明为记忆用途的设施（如 memory MCP）；环境未声明时，视为没有。项目指 `.agents/memory/`，仅用户明确要求时新建；新建前先确认项目根和位置，登记入口后一次建齐，不预建空文件。若没有已声明的记忆设施，照常工作即可。

## 写入

写入遵循知情制：

- 硬红线：禁止在用户不知情的情况下写入全局记忆或项目记忆。
- 判断价值：下次如果忘记它，会不会导致重复踩坑、重复询问、违反已确认决定或重新验证？会，才值得询问；判断不了时，说明理由，让用户决定。
- 认为有价值时，问用户：「这件事有记忆价值，要不要写」，并附推荐归属和位置。
- 用户主动要求记住，视为显式授权，直接写入；写完后报告写了什么、写到哪。
- 敏感信息（密码、密钥、token、私钥、完整 `.env`）不得写入记忆。记忆里的事实须已验证；未确认的内容标明状态。
- 通用内容只写全局，项目特例只写项目；冲突时，当前项目内以项目特例为准，并向用户说明。

## 读取

读取无需确认：先读入口或索引，再按当前任务读相关主题。只使用环境或项目明确声明的记忆设施；Agent 安装目录、配置目录不是记忆位置。若与当前用户指令或已验证事实冲突，按最新确认结果处理，并指出冲突。

## 多 Agent 与并发

多 Agent 场景下，只有能与用户交互的主 Agent 可以实际变更记忆；子 Agent 只提交候选、证据和推荐位置。与旧记忆冲突时，展示旧内容和新证据，提出更新或废弃建议，等待用户确认。写入后重新读取，核对实际保存的内容和位置；没有验证成功，不得声称已经记住。

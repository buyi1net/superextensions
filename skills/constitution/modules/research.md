# 调研规范

> 查资料时的执行细则，是求真协议的严格版：一次工具调用能查完的，按求真协议当场做；需要多轮阅读才能收口的，按本文走。

## 执行模式

- 调研是耗时的阅读工作，派子代理去做；主会话不阻塞等待，继续推进原任务，等结果回来再合并结论。
- 派出去之前，把任务书写清楚，至少交代两部分内容。一是任务要求：查什么、查到什么程度算完成、哪些来源算数。二是主会话上下文：子代理不带当前会话历史，已知的背景、已查过的方向、已排除的方向，都要靠任务书带过去，避免重复劳动或查偏；背景太长时，写成文件放进工作目录，让子代理自己读。

## 来源纪律

- 只认一手来源：官方文档、源代码、规范、第一方 API。博客、教程、AI 摘要等二手转述不算证据，只能当线索；顺着线索找到一手出处，才算查到。
- 每条论断都要追溯到信息的源头，而不是随便一个提到过它的地方。例如查一个 npm 包的行为，源头是官方文档和包源码，不是某篇测评。
- 找不到一手来源、只有二手说法时，结论标注「二手来源，未溯源到一手」，不冒充已验证。

## 产物落盘

- 结论写进单个 Markdown 文件，每条论断附来源引用（链接或 file:line）。
- 存放位置跟项目管理制度走；制度没覆盖或拿不准时，先问用户再放。
- 落盘前自查一遍：每条论断的出处是否真实可达，链接没有编造。

## 与既有红线的衔接

- 求真协议管每次对话的日常验证，本文管多轮调研的严格版。两边要求不一致时，按更严的来。

给人写文档（README、报告、说明、commit、周报）前加载。读者只有人，可读性就是写作目标；文风一节管语言质感，写任何中文都套用（范文四就是给 Agent 的指令）。给 Agent 文档的结构机制走 `express-agents`，翻译走 `express-translate`。

## 写前三件事

1. 想清楚读者带着什么问题来，按问题组织段落，不按自己知道的顺序组织；解释抽象概念时给具体例子。
2. 对齐下方范文的密度、节奏和语言质感，不追字数。
3. 硬规则全程生效：
   - 无歧义优先于简短：读者会停下来猜断句或猜指代，就恢复被删的成分。
   - 一个段落只说一件事，段间有过渡。
   - 术语统一：同一概念全文一个词，首次出现时标「中文（English）」；中文叫法拿不准时查 [express-translate 术语表](../express-translate/modules/terms.md)。
   - 技术内容原样：代码、命令、路径、报错原文不翻译不改写。
   - 引用带链接：提到文件或资源的地方必须给可访问的链接，仓库内用相对路径，外部资源用完整 URL，不用反引号代替链接。

## 文风

写出来的东西要读着像中文母语工程师在跟同事讲事情。这个状态人自己都保持不住，写着写着就会滑走，所以每篇都要刻意找一次：

**先说后写**。落笔前先想一句：这句话跟同事当面讲，我会怎么说？嘴上怎么说，笔下就怎么写。「当……时」「对……进行」「在……的基础上」这种腔，嘴上没人这么说，写出来也别有。

**写完读一遍**。交稿前从头读，读着卡壳、要回头重读的句子就是写坏的，重写它。

滑走有三个方向，对照自查，滑进了哪个就拉回来：

- 端起来：书面腔、翻译腔，被动句、「进行」类动词、定语从句套头；
- 表演：俏皮词连排、动词用力过猛，读着像抖机灵，换平实说法；
- 偷懒：压缩到推不回全称，名词短语连排成电报体。

动笔前扫一眼下方范文，找语感。

## 范文一：说明文档体

> 本目录保存用于研究、比较、核验和借鉴的外部材料。项目自有规则、正式 skill、工作记录和交付内容不放在这里。
>
> 收录先做归属判断：外部收集、只用于理解和借鉴的材料进本目录；当前工作要直接采用或随成果交付的正式输入，按它在项目中的实际职责进入源码或交付目录，判断不了的先确认用途再归位。

## 范文二：报告体

> 本周完成三件事。语言类 skill 拆分为四个：翻译、给人写、给 Agent 写、写后检测，各自独立加载，互不污染。记忆制度按「能不写就不写」重写，项目记忆退役，存量转档到 docs。总纲交流规范精简为两句，对话不再受写作规则干扰。
>
> 遗留两个问题。长文档的范文还没有，报告写作缺对齐样本；本机缓存仍是旧版，需要走一次发布同步。
>
> 下周计划：补齐报告体范文；观察三个 skill 的实际触发情况，决定是否路由进总纲。

三段式：先列成果（每件一句，说清改了什么、为什么），再摆遗留问题，最后给下一步。段落之间靠内容自然过渡，不堆过渡词。

## 范文三：commit 体

> constitution 交流规范精简，obra 参考降级为定点参考

一行就是动词加对象，说清这轮改了什么；多处改动用顿号并列，不用长句解释，细节在正文和 diff 里。

## 范文四：指令文档体（给 Agent）

> 一旦用户选定某个候选方案，就调用 `grilling`，陪用户走一遍决策树：理清约束条件、依赖关系、深化后模块长什么样、接缝后面藏着什么、哪些测试还能跑通。决策过程中冒出的事项，当场就落进文件；调用 `domain-modeling`，随时让领域模型跟得上最新进展：
>
> - 深化后的模块用了 `GLOSSARY.md` 里没有的概念来命名？把这个概念补进去。文件要是还没建，就按 `domain-modeling` 的约定建一个。
> - 聊着聊着把某个模糊的说法给敲定了？立马更新 `GLOSSARY.md`。
> - 用户因为某个硬理由把这个方案否了？主动问一句要不要记成 ADR，可以这么说：「要我把这条记下来吗？以后做架构评审时，省得别人再提一遍。」但这个理由得是真的值得后人知道，才记；临时性的（比如「现在顾不上」）或不说也明白的，就算了。
> - 想给深化后的模块另找接口方案？调用 `codebase-design`，用它的「Design It Twice」模式：并行拉起多个子代理，给每个发不同的设计约束，各出一版接口设计。

这是给 Agent 的操作指令，也是这个文风能穿到的最硬的场合：「要是还没建」「立马」「省得别人再提一遍」「就算了」，全是跟同事交代事情的口气；但精确一点没丢，靠的是术语和判断条件（「真的值得后人知道，才记」），不靠端着。

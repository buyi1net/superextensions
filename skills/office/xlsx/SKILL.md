# XLSX 电子表格创建、编辑与分析

| 任务类型                                             | 处理路线                                                                                                                                     |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **从零创建**或带公式与样式的**编辑修改**             | 使用 `openpyxl` 编写脚本，动手前务必阅读下文的避坑指南                                                                                       |
| **海量原始数据**的高速批量导入导出                   | 使用 `pandas`（`read_excel`、`to_excel`）                                                                                                    |
| **快速速览**某个工作表内容                           | 运行 `markitdown file.xlsx`：每个工作表对应一个 `## 工作表名` 二级标题；同样兼容 `.xlsm`。注意它不输出具体单元格坐标，切勿据此规划单元格改动 |
| **完整读取**模型文件（同时需要公式文本*和*计算数值） | 分两次执行 `load_workbook`（详见下文说明）                                                                                                   |

> 当前环境中已预装 `openpyxl`、`pandas` 和 `markitdown`，无需运行 `pip install`，直接在 Python 脚本中 import 即可。只有当 import 抛出 ModuleNotFoundError 或缺少 `markitdown` 命令时，才针对性安装缺失的包。

> 下文所有脚本路径均相对于本 skill 所在目录。

## 每一份交付文件都必须达标的硬性规范

- **全局统一使用专业正文字体**（如 Arial、Times New Roman），除非用户有明确特殊要求。
- **计算公式零报错**：只要 `recalc.py` 报告 `errors_found`，该文件就绝对不能交付。如果你怀疑某个公式报错是在你接手前就存在的，请用事实证明：用 `data_only=True` 重新加载**原始输入文件**并核查该单元格。你自己写错导致的公式报错，与前人遗留下来的报错长得完全一样。
- **必须使用真实公式，严禁硬编码填死计算结果**：写入 `sheet['B10'] = '=SUM(B2:B9)'`，绝不能直接把 Python 在内存里算好的合计数字填死。当用户修改输入单元格的数据时，整个工作簿必须能够自动联动重算。
- **逐字严格遵循用户需求规格**：精确的工作表标签名（Tab Name）、一字不差的表头文案、以及用户指定的计算公式。哪怕你重新设计的版面再优雅，只要算出的业务指标与用户指定的不符，都是交付失败。
- **在读者一眼就能看到的地方，标明每一个假设前提和硬编码常数**：可以写在单元格批注（Comment）里，也可以标注在表格末尾的紧邻单元格中。如果数据有出处，必须附带真实引用来源（例如 `数据来源：公司 2024 财年 10-K 年报，第 45 页，营业收入附注，[SEC EDGAR 链接]`）；如果是用户口头提供的数据，直接如实写明。
- **由你从零新建、供他人填写的空白采集模板**：必须在醒目位置附带简明图例指明哪些单元格是待填项，并填入一行逼真的示例数据以展示预期格式。如果是用户让你修改既有文件，绝不要擅自添加这种示例行。
- **编辑修改既有文件：必须 100% 贴合原文件的排版习惯与规范**。原文件已有的视觉规范高于本文档中的任何通用建议。动手前先观察原文件划定的输入区域（通常会有特殊的字体颜色、底色填充或边框阴影），仅在这些指定位置写入，切勿随意改动已有的公式体系。

## 重新计算 Recalculate（只要包含公式就必须强制执行）

`openpyxl` 在将公式写入表格时，仅仅是把公式作为纯文本字符串存入底层 XML，**完全不会生成任何缓存计算值**。在执行重新计算之前，任何依赖缓存值读取数据的工具（包括 `pandas`、`load_workbook(data_only=True)` 以及绝大多数预览器），读取这些公式单元格的结果全部都是 `None`。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # 默认超时时间为 30 秒
```

该脚本会在后台驱动无头 LibreOffice 计算文件内的每一个公式，并将计算结果**原地覆写保存**回原文件。执行后会输出一段 JSON 报告：
包含 `status`（`success` 或 `errors_found`）、`total_formulas`（公式总数）、`total_errors`（报错总数），以及列出每种错误类型最多 100 个出错位置的 `error_summary`（若出现 `locations_truncated`，说明还有超出部分未展示，必须以 `total_errors` 为准，不要只数列表项个数）。根据提示修复代码并再次运行。**如果返回的 JSON 包含 `error` 键而不是 `status`，说明根本没有完成重算**，且只有这种异常情况才会以非零状态码退出（`errors_found` 退出码仍然是 0，因此千万不要把命令退出码为 0 当作工作簿没有错误）。

**重算通过（全绿）只能证明你的公式“语法合法、能算出值”，并不代表“计算逻辑正确”。** 如果求和范围偏移了一行，或者引用了错误的行号，同样会产出一份干干净净、零报错但数字全错的文件。在批量生成整张表格前，先写 2-3 个代表性公式，亲自核实算出来的数字是否符合预期。

**如果原表格引用了外部工作簿文件，使用 openpyxl 保存并重新计算会导致外部链接全部失效丢失。** 这类公式形如 `='[1]Returns Analysis'!$B$2`，其中的 `[1]` 是当前工作簿外部引用列表的索引编号，指向的是**磁盘上的另一个独立文件**，而非当前文件内的工作表。在当前运行环境中，那个外部文件往往并不存在，因此单元格内原本缓存的历史值是保留该数据的唯一存根。`openpyxl` 在保存时会清空这个缓存值；随后 LibreOffice 尝试真实解析该引用，因找不到外部文件而失败，最终写入 `#NAME?` 并把整个外部链接彻底抹除。`recalc.py` 遇到这种情况会直接拒绝运行：在覆写保存之前，务必先把这些单元格的历史值从原始文件中提取出来（`--force` 参数可以强制执行，但这等于主动接受链接丢失）。

## 挑选能稳定通过校验的公式函数

当前环境下运行的 LibreOffice 内置函数库比最新版 Microsoft Excel 略少。任何它无法识别的函数，都会直接变成硬编码的 `#NAME?` 留在交付文件里。

- **优先选用 Excel 2007 时代的经典函数**：例如 `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT` 等，这些经典函数不需要任何特殊前缀，全平台兼容极佳。
- **2007 年后新增的常用函数中有 6 个可用，但必须手动补上 `_xlfn.` 前缀**：这是因为 `openpyxl` 是逐字把公式文本写进底层 XML 的，而 Excel 在底层 XML 中就是带此前缀存储这批新函数的（只是在客户端界面上自动隐藏了前缀）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。如果裸写函数名而不带前缀，重算时一律报错 `#NAME?`。
- **严禁使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`**：当前运行时的 LibreOffice 无论加什么前缀都无法计算它们。即便较新版本的 LibreOffice 支持计算，它们也是动态数组溢出函数（Spilling array functions），而 `openpyxl` 导出的文件缺失动态数组所需的底层元数据，导致最终只有左上角的一个单元格能拿到值。最危险的是，`recalc.py` 在面对这种被截断的结果时还会误报 `total_errors: 0`。查找匹配请统一改用经典的 `INDEX` + `MATCH` 组合；排序、过滤、去重等操作，请先在 Python 层面处理好后再写入单元格。
- LibreOffice 无法解析的公式，写回文件时会被强制转换成**全小写**：单元格里如果出现全小写的函数名并伴随 `#NAME?`，是典型的函数未识别特征。

## openpyxl 避坑指南

- **读取模型文件必须加载两次**：设置 `data_only=True` 只能拿到缓存的数值，所有公式全部丢失；默认模式只能拿到公式文本，拿不到计算结果。单次加载不可能二者兼得。
- **在 `data_only=True` 模式下执行保存是毁灭性的**：此时工作簿里的公式已经全部被剥离，一旦调用 `wb.save()`，所有公式都会被永久替换为静态死值。
- **在 openpyxl 刚刚写出的文件上直接用 `data_only=True` 读取，所有公式单元格都是 `None`**：必须先跑 `recalc.py` 让底层重新计算一遍。（计算结果为空文本 `""` 的公式读回来同样是 `None`。）
- **合并单元格（Merged Cells）：只能在左上角的锚点单元格写入**。合并区域内的其他从属单元格全部是只读的 `MergedCell` 代理对象，给它们的 `.value` 赋值不会生效。
- **`.xlsm` 启用宏的工作簿在 `load_workbook` 时必须传入 `keep_vba=True`**，否则文件内的 VBA 宏代码会被全部清除丢弃。
- **跨表引用时，若工作表名称包含空格，必须用单引号包裹**：形如 `='Assumptions Inputs'!$B$5`。若漏掉单引号，公式重算时会直接报错 `#VALUE!`。

## 商务与财务模型排版规范

除非用户另有要求，或既有文件已形成了特定习惯：

**色彩语义规范：**

- **蓝色字体**（`0,0,255`）：用于硬编码输入值、业务假设和情景开关。
- **黑色字体**：用于所有计算公式和表头标题。
- **绿色字体**（`0,128,0`）：用于跨工作表引用的链接单元格。
- **红色字体**（`255,0,0`）：用于跨外部文件的链接单元格。
- **黄色背景填充**（`255,255,0`）：用于核心假设输入区以及需要读者手动填写的单元格。

**数字与格式规范：**

- 货币金额统一使用 `$#,##0`，并在列头或表头标明计量单位（如 `营业收入（百万美元）`）。
- 零值统一显示为破折号 `-`，百分比中的零值同样适用（数字格式设为 `$#,##0;($#,##0);-`）。
- 负数统一使用括号包裹，如 `(1,250)`。
- 百分比统一使用 `0.0%`，**且底层必须以小数形式存储**（存储 `0.15` 显示为 `15.0%`；若直接存入 `15` 会被渲染成 `1500.0%`）。
- 估值倍数格式设为 `0.0x`。
- 年份统一存为文本格式（`"2024"`，绝不能写成带千分位的数字 `2,024`）。

**结构与公式规范：**

- 每一个业务假设都必须拥有带明确标签的独立单元格，供下游公式引用（例如公式写为 `=B5*(1+$B$6)`，绝不要硬写成 `=B5*1.05`）。
- 同一行在预测期内的公式必须保持横向一致性：行中间突然出现单独手调的单元格是财务模型中最常见的隐蔽致命错误。
- 对所有可能为零的分母增加除法保护（例如配合 `IFERROR` 或判断 `IF(B5=0, 0, ...)`）。

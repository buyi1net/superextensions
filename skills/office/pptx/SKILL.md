# PPTX 演示文稿创建、编辑与分析

`.pptx` 文件本质上是一个打包了多个 XML 文件的 ZIP 压缩包。请根据具体任务选择对应的处理路线：

| 任务类型                         | 处理路线                                                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **从零创建**新幻灯片             | 编写基于 `pptxgenjs` 的脚本，动手前务必阅读下文的避坑指南                                                                                         |
| **编辑**已有文稿，或基于模板制作 | 解压 `unzip` → 修改 `ppt/slides/slideN.xml` → 重新打包 `zip`                                                                                      |
| **快速提取**幻灯片文字           | 运行 `markitdown deck.pptx`（每页对应一段带有 `<!-- Slide number: N -->` 标记的内容）；视觉网格速览可运行 `python scripts/thumbnail.py deck.pptx` |

## 辅助脚本速查

以下脚本路径均相对于本 skill 所在目录。其余操作均使用标准 Python、`node` 或系统命令。

| 脚本                                                              | 功能与注意事项                                                                                                                                                                                                       |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/thumbnail.py deck.pptx [前缀]`                           | 生成标有每页序号的网格缩略图，便于挑选模板版式。仅支持 `.pptx`。**必须传入前缀参数**：默认前缀为 `thumbnails`，若同一目录下处理多份文稿，后一次生成会直接静默覆盖掉前一次的图片                                      |
| `scripts/add_slide.py unpacked/ slide2.xml [--after slideN.xml]`  | 复制一张幻灯片（或某个 `slideLayoutN.xml` 版式），并自动维护压缩包内的所有引用映射。支持直接处理文件：`add_slide.py deck.pptx slide2.xml -o out.pptx`                                                                |
| `scripts/clean.py unpacked/`                                      | 彻底清理未被引用的孤立幻灯片、媒体文件和关系映射（rels）。必须在最终确定 `<p:sldIdLst>` **之后**再运行                                                                                                               |
| `scripts/office/validate.py deck.pptx [--original src.pptx]`      | 执行 XML 架构（Schema）、引用关系、内容类型（content-type）、图表和幻灯片结构校验；报错时会给出修复建议。基于模板修改时**必须加上 `--original`**：它会以原模板为基线，避免把模板自带的历史校验问题误报为你引入的错误 |
| `scripts/office/soffice.py --headless --convert-to pdf deck.pptx` | LibreOffice 包装脚本：在当前沙箱环境中直接调用原生 `soffice` 会引发死锁挂起                                                                                                                                          |

## 用 pptxgenjs 创建幻灯片（避坑指南）

当前环境已预装 `pptxgenjs`，无需运行 `npm install`，直接在脚本中 `require('pptxgenjs')` 即可（仅在 require 报错时才执行 `npm install pptxgenjs`）。虽然 LLM 熟悉其常用 API，但极易踩入以下导致文件损坏或排版崩塌的暗坑：

- **添加幻灯片前，必须先设置 `pres.layout`。** 默认画布为 `LAYOUT_16x9` = **10 英寸 × 5.625 英寸**，并不是常见的 13.3 英寸宽（宽屏应当显式设置为 `LAYOUT_WIDE`：13.3" × 7.5"）。如果坐标超出画布边缘，代码虽然能正常写入且不报错，但元素会直接跑到幻灯片可视区域之外。
- **十六进制颜色：绝对不要加 `#`，绝对不要传 8 位字符。** 标准写法为 `color: "FF0000"`。如果写了 `"#FF0000"` 或在 hex 中塞入透明度（如 `"00000020"`），**会导致文件损坏、PowerPoint 无法打开**。设置透明度时：填充和图片使用 `transparency: 0-100`，阴影使用 `opacity: 0.0-1.0`；这两个属性互不通用，配错位置会被静默忽略。
- **pptxgenjs 会就地修改（mutate）传入的 options 配置对象**（首次使用时会在对象内部将数值转为 EMU 单位）。因此，绝对不要在多次 `add*` 调用之间复用同一个配置对象或阴影对象，每次调用都必须重新构建独立的新对象。
- **阴影的 `offset` 偏移量必须 ≥ 0**：传入负数会导致文件损坏。如果需要向上投射阴影，请使用正数偏移量配合 `angle: 270`。
- **`letterSpacing` 属性会被静默忽略**：设置字间距的正确属性名为 `charSpacing`。
- **列表项排版**：必须为每个列表项单独声明 `bullet: true`，严禁在文本中手动拼接圆点字符 `•`（否则会渲染出双重圆点）。除数组中最后一项外，前面每项都要加上 `breakLine: true`。带项目符号的段落间距请使用 `paraSpaceAfter`，切勿使用 `lineSpacing`（否则会导致巨大的行间空隙）。
- **每个输出文件对应一个独立的 `new pptxgen()` 实例**，严禁跨文件复用实例。
- **`rectRadius` 圆角半径仅对 `ROUNDED_RECTANGLE` 生效**，对普通 `RECTANGLE` 无效。
- **该库不支持渐变填充（Gradient fills）**：若需渐变质感，可生成一张渐变图片作为幻灯片背景。
- **文本框自带默认内边距（padding）**：当文字需要与相同水平坐标（x 轴）处的图形、线条或图标对齐时，务必给文本框加上 `margin: 0`。
- **演讲者备注必须写入 `slide.addNotes("...")`**（纯文本，每页仅调用一次），绝对不能把备注写进幻灯片上的文本框里。
- **优先保持原生图表（Native Charts）**：PowerPoint 原生支持的图表类型全部使用 `addChart()` 生成（组合图传入 `{type, data, options}` 数组）。对于 PPT 原生支持但该库未开放的特性（如趋势线、误差线），可通过自行计算辅助数据系列或后处理生成的 OOXML 实现，切勿退化成静态图片。只有 PPT 本身完全不支持的图表类型（如桑基图、网络拓扑图、弦图等），才允许转成图片插入。
- **默认图表效果极度粗糙**：默认没有标题、没有数据标签且配色陈旧。务必显式配置 `showTitle` + `title`、`showValue: true` + `dataLabelPosition`、自定义 `chartColors: [...]` 调色板，并弱化图表背景网格线（配置 `catAxisLabelColor`/`valAxisLabelColor`、`valGridLine: { color, size }`、`catGridLine: { style: "none" }`，并在单数据系列时设置 `showLegend: false`）。
- **在堆叠条形图或堆叠柱状图上，`dataLabelPosition` 只能设为 `ctr`、`inEnd` 或 `inBase`。** 若设为 `outEnd` **会导致文件彻底损坏**。
- **包含次坐标轴（`secondaryValAxis`/`secondaryCatAxis`）的组合图，必须在图表选项中同时显式声明 `valAxes` 和 `catAxes`，且各提供两组配置项。** 若遗漏声明，pptxgenjs 会写入从未定义过的坐标轴 ID，PowerPoint 会**直接丢弃该图表**并弹窗提示文件已损坏。仅声明 `valAxes` 是不够的。
- **调用 `writeFile()` 后，必须运行 `python scripts/office/validate.py deck.pptx`。** 该脚本能检测出上述两个图表暗坑以及 PowerPoint 拒绝加载的 XML 语法缺陷，并明确给出修复方案。请直接在生成代码中修正，不要尝试手动修补打包后的 XML。
- **绝对不要重排 `<p:presentation>` 内部的子节点顺序。** pptxgenjs 会将 `<p:notesMasterIdLst>` 紧排在 `<p:sldIdLst>` 后面并将两个母版指向同一主题部件。PowerPoint 可以正常识别这种结构，但只要挪动了该节点的位置，整份文稿就会变成无法打开的损坏文件。
- **矢量图标引入方案**：将 `react-icons` 渲染为 SVG（通过 `ReactDOMServer.renderToStaticMarkup`），使用 `sharp` 在 ≥256px 分辨率下栅格化，再通过 `addImage({ data: "image/png;base64," + buf.toString("base64") })` 插入，必须保留 `image/png;base64,` 前缀（相关 npm 库均已预装）。

## 编辑已有演示文稿与模板

挑选版式时，先生成缩略图：运行 `python scripts/thumbnail.py template.pptx template-thumbs`。脚本会生成带有每页序号的网格图，并打印输出路径（12 页以内为 `template-thumbs.jpg`，超过 12 页会拆分成 `template-thumbs-N.jpg`）。**注意：第二个参数必须显式传入，建议直接用文稿名命名**。若省略该参数，默认前缀是 `thumbnails`，同一目录下处理多份文稿时，后一次生成会直接静默覆盖掉前一次的网格图。（注：缩略图仅用于挑选版式；视觉质量验收请使用后文 [转换为图片](#转换为图片) 中的高分辨率渲染图；脚本仅接受 `.pptx`，若为 `.potx` 模板请先复制改名为 `.pptx` 后缀）。结合 `markitdown` 将每个内容段落映射到对应的模板版式上，注意版式多样化，切勿每页都千篇一律套用“标题 + 圆点列表”。

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('unpacked')" deck.pptx
python scripts/add_slide.py unpacked/ slide2.xml --after slide2.xml   # 复制一张幻灯片（或 slideLayoutN.xml）；终端会输出新幻灯片路径
# 调整顺序或删除幻灯片：编辑 ppt/presentation.xml 中的 <p:sldIdLst>
python scripts/clean.py unpacked/                                     # 完成页面增删后运行：清理孤立无引用的幻灯片、媒体文件和关系映射
# 原地编辑幻灯片内容：ppt/slides/slideN.xml
(cd unpacked && rm -f ../out.pptx && zip -Xr ../out.pptx .)           # 务必在解压目录内部打包；先 rm 输出文件，否则被删部件仍会残留
python scripts/office/validate.py out.pptx --original deck.pptx
```

- **必须在修改幻灯片具体内容之前，先完成所有结构调整（添加、删除、重排）。** `add_slide.py` 是逐字完整克隆幻灯片文件的，如果在编辑内容后再克隆，会把改好的文字一并拷过去；而 `clean.py` 会直接删除所有未在 `<p:sldIdLst>` 中登记的页面，包括你刚刚写好的那页。
- **绝对不要手动拷贝幻灯片 XML 文件**：`add_slide.py` 会自动完成新页面在整个压缩包内的全部登记，并汇报生成结果（例如 `Created ppt/slides/slide17.xml from slide2.xml`）。该脚本也支持直接操作文稿文件：`add_slide.py deck.pptx slide2.xml -o out.pptx`，**务必传入 `-o`，否则会原地覆写原文件。** 注意：克隆出的幻灯片依然引用源页面的图表、SmartArt 和嵌入对象部件（浅引用），而不是独立深拷贝副本，因此修改一页的图表会同时影响另一页。
- **使用 `python-pptx` 时需警惕的三大限制**：它无法克隆已有幻灯片（唯一的加页入口是 `add_slide(layout)`）；直接赋值 `text_frame.text = "..."` 会冲掉原有样式并将段落塌陷为未格式化的单一行（必须赋值给 `run.text`）；无法读取大多数商务模板中内嵌的 SVG/EMF 矢量图（调用 `add_picture` 会抛出 `UnidentifiedImageError`）。
- 旧版 `.ppt` 文件必须先转格式：`python scripts/office/soffice.py --headless --convert-to pptx file.ppt`。`.potx` 模板的解压与打包流程完全相同，输出文件保持 `.potx` 扩展名即可。
- 如需复用模板中的图标或装饰元素，直接克隆已经包含该元素的幻灯片或版式即可。

填充模板内容时的细节规范：

- 编写脚本转换 XML 时，必须使用 `defusedxml.minidom` 解析：用标准库 `xml.etree.ElementTree` 往返解析 OOXML 会重写命名空间前缀，导致文件损坏。
- **模板插槽数量 ≠ 实际数据条目数量**：如果模板设计了 4 位团队成员卡片而你只有 3 位，必须把第 4 位的整组元素（头像 + 文本框）彻底删掉，而不是只清空文字，并在后续 QA 验收中检查是否有孤立残留的装饰边框或底色块。
- 每个列表项独占一个 `<a:p>`：绝不能把多个项目拼在同一段里。复制同级 `<a:pPr>` 以继承间距设置，并在小标题、小节前缀和行内标签（如 `状态:`、`负责人:`）的 `<a:rPr>` 上添加 `b="1"` 加粗。
- 让项目符号直接从母版版式中继承；仅在需要覆盖默认样式时才添加 `<a:buChar>`、`<a:buAutoNum>`（自动编号）或 `<a:buNone>`，正文里严禁手写字符 `•`。
- 首尾包含空格的文本，必须在其 `<a:t>` 节点上声明 `xml:space="preserve"` 属性。

## 幻灯片设计建议

**拒绝粗制滥造与平庸版式。** 纯白背景配干瘪的黑圆点列表无法打动任何人。在规划每一页时，请参考以下设计准则：

### 动手前构思

- **选用鲜明且切合主题的专属配色**：调色板应当让人一眼看出是为当前主题量身打造。如果把这套配色直接套用到完全无关的汇报里也毫不违和，说明色彩选择过于平庸通用。
- **主次分明，切忌平分秋色**：必须有一种主导色彩占据全局 60-70% 的视觉比重，搭配 1-2 种辅助色以及一种醒目的点缀色，绝不要让所有颜色均分画面。
- **深浅对比**：封面标题页与封底结语页使用深色背景，中间正文内容页使用浅色背景（经典的“三明治”层次）；或者全篇贯彻高级深色调。
- **贯穿一个核心视觉母题（Motif）**：全篇反复呼应同一个鲜明的视觉特征，例如统一的圆角图片裁切、统一带彩色圆底的图标风格。**严禁把单边彩条或装饰横线当作视觉母题**（详见下文避坑清单）。

### 推荐调色板灵感

### 每一页幻灯片的构成要素

**每一页都必须包含视觉锚点**，如图片、图表、图标或几何卡片，纯文字页面极易让人产生阅读疲劳。

**常用排版布局：**

- 双栏对照（左侧提炼文字，右侧搭配大图或图表）
- 图标卡片行（彩色圆底图标 + 粗体小标题 + 简要说明文字）
- 2x2 或 2x3 网格卡片（一侧为整幅大图，另一侧为信息卡片矩阵）
- 半幅通栏大图（左半侧或右半侧占满），配内容文本覆盖层

**数据呈现手法：**

- 巨幅统计数字标注（60-72pt 超大数字，下方配紧凑说明标签）
- 并列对比栏（改造前/后对比、优缺点权衡、多方案并列）
- 流程与时间线（带序号的推进步骤、引导箭头指示）

**视觉润色细节：**

- 小节标题左侧点缀带底色的小圆底图标
- 关键指标、核心结论或标语使用斜体或点缀色进行强调

### 字体排版与字体安全表

**写入 .pptx 的字体最终是在打开文件的用户电脑上渲染的，而非当前服务器环境。** 你的视觉 QA 是通过无头 LibreOffice 进行渲染的，若环境中缺少指定字体，LibreOffice 会使用备用字体替换，某些替代字体的字宽与原字体差异很大，这会导致你在 QA 预览图里看到的“刚好放下”或“文字溢出”，在用户真正的 PowerPoint 中完全是另一回事。为了保证验收可靠性：

- **绝对安全字体清单**（在 QA 环境中按真实字宽渲染，且在 Windows / Mac Office 中全局预装）：**Arial、Calibri、Cambria、Times New Roman、Courier New、Bookman Old Style、Century Schoolbook**。正文排版以及对换行溢出敏感的内容，必须选用此清单内的字体。
- **零 QA 风险的高质感搭配**：使用安全清单中的衬线字体作为大标题（Cambria、Bookman Old Style、Century Schoolbook），搭配安全清单中的无衬线字体作为正文（Calibri 或 Arial）。既能拉开鲜明的视觉质感，又不会失掉文字溢出检测的准确性。
- **若用户指定了安全清单之外的字体**（如 Georgia 或 Trebuchet MS）：在用户指定处使用，但设置文本框大小时务必额外预留 ~10% 的缓冲余量，不要盲信 QA 预览中极限贴边的效果。如果用户未指定，正文一律优先选用安全字体。
- **QA 不可靠字体**（替代字体的字宽偏差显著，溢出检查容易误判）：Georgia、Trebuchet MS、Impact、Arial Black、Garamond、Consolas、Palatino Linotype；Calibri Light 在各系统上的替代情况差异极大，同样视作不可靠。此类字体若留足余量用于大标题尚可，但不要依赖 QA 预览去做精细排版。
- **绝对不要默认使用 Aptos**：微软 Office 在 2023 年后采用的新默认字体在 Linux 沙箱环境中缺少等宽替代字体，且在旧版 Office 中普遍缺失，两头都不讨好。

| 元素类型      | 建议字号         |
| ------------- | ---------------- |
| 幻灯片大标题  | 36-44pt 粗体     |
| 小节/卡片标题 | 20-24pt 粗体     |
| 正文说明      | 14-16pt 常规     |
| 备注与角标    | 10-12pt 弱化色彩 |

### 间距留白

- 画布四周安全边距至少保留 0.5 英寸
- 各内容块、卡片之间保持 0.3-0.5 英寸间距
- 留出充足的呼吸空间，严禁把版面的每一寸空隙都填满

### 避坑清单（大模型常见低级错误）

- **不要通篇重复单一版式**：跨页灵活切换两栏、三卡片和数据大字版式。
- **正文严禁居中对齐**：段落正文和列表一律左对齐，只有大标题允许居中。
- **字号阶梯要拉开**：标题至少 36pt 以上，才能与 14-16pt 的正文拉开清晰的视觉层级。
- **切忌无脑套用科技蓝**：根据具体业务挑选契合的色彩基调。
- **间距节奏要统一**：全局统一选用 0.3" 或 0.5" 的间距，切勿忽大忽小。
- **拒绝“虎头蛇尾”**：不能只精心打磨前几页而让后面几页裸奔；要么全篇保持设计感，要么全篇走极简风。
- **拒绝纯文字幻灯片**：每一页都应包含图片、图标、图表或几何视觉元素，杜绝干瘪的“标题 + 圆点列表”。
- **注意文本框的默认内边距**：线条或形状要与文字边缘对齐时，记得给文本框加上 `margin: 0`，或者手动算入内边距偏移。
- **警惕低对比度**：图标和文字都必须与背景有强烈的明暗反差，切忌“浅底浅字”或“深底深字”。
- **严禁在标题下方画强调短线**：这是大模型生成幻灯片最典型的塑料痕迹；请利用充足的留白或背景色块来划分层级。
- **严禁添加毫无意义的装饰色彩条**：严禁在页面顶底拉通栏色条、在侧边贴单侧装饰条、在卡片边缘加单边彩条。这些都是浓浓的 AI 劣质填充感。若要突出某张卡片，请使用低饱和度背景底色、轻微阴影或搭配图标，绝不要贴边缘彩条。
- **切勿默认米黄/奶油色背景**：未指定背景时，直接使用纯白（`FFFFFF`）或用户指定的品牌色；不要盲目套用 `F5F5DC`、`FAF0E6`、`FAEBD7`、`FFF8E1` 等暖灰米色。
- **绝对不能让文字溢出容器**：文字放不下时，缩小字号、分页排版或拉大容器，绝不能让文字被截断或漫出边框。

## QA 质量验收（强制闭环流程）

初次生成的文稿往往会有一些实际问题，如元素重叠、文字溢出、对齐偏差。务必找出并修好它们，只针对改动过的页面重新渲染核对，确认无误后再交付。

### 1. 内容文本 QA

```bash
markitdown output.pptx
```

检查是否有遗漏内容、错别字或顺序颠倒。

**在使用模板时，务必检索是否有残留的占位符文本：**

```bash
markitdown output.pptx | grep -iE "\bx{3,}\b|lorem|ipsum|\bTODO|\[insert|this.*(page|slide).*layout"
```

如果 grep 匹配出结果，必须修正后再宣布完成。

### 2. 底层文件结构 QA（强制执行）

```bash
python scripts/office/validate.py output.pptx                      # 全新生成的文稿
python scripts/office/validate.py output.pptx --original src.pptx  # 基于模板改建的文稿
```

**如果文稿源自模板，必须带上 `--original`。** 模板自身可能就包含通不过 XSD 校验的部分，裸跑会报出并非由你造成的错误，从而把真正新引入的回归问题淹没在报错声浪中。`--original` 会将架构与幻灯片检查以原模板为基线，过滤掉原模板已有的旧毛病。而结构性检查（引用关系、内容类型、图表）则不受 `--original` 过滤，两边都会报告，请按提示修复。

pptxgenjs 很容易生成 PPT 无法打开、而其它工具（python-pptx、LibreOffice、XSD）均能正常加载的非法图表 XML。每一处错误提示都会给出具体修正方法，请直接在生成代码中修复并重新打包。

### 3. 视觉效果肉眼 QA

将幻灯片转换为图片（见后文 [转换为图片](#转换为图片)），并逐页检查渲染图。刚写完代码时人的大脑往往倾向于看到自己“以为会渲染出的画面”，而不是“真正渲染出的图像”，因此必须以空杯心态审查图片（如果有条件，派发给单独的子 Agent 来复核效果很好）。需要排查的用户可见缺陷清单：

- **文字溢出或在文本框/幻灯片边缘被截断（首要检查项）：** 这是最高频且用户一眼就能看见的瑕疵。（根据前文“字体排版”规则，对于 QA 预览不可靠的字体，以你预留的 ~10% 间隙为准，不要迷信预览截图中的贴边效果。）
- 元素相互重叠（文字穿透形状、线条横切文字、元素叠成一团）
- 来源引注文档或页脚与上方正文撞车
- 间距过窄（小于 0.3"）或卡片模块几乎贴合在一起
- 间距节奏不均（一处大片空旷，另一处拥挤逼仄）
- 距幻灯片四周的安全边距过小（小于 0.5"）
- 多列或并列卡片没有对齐基准线
- 文字对比度过低（例如米色底配浅灰字）
- 文本替换后模板装饰元素发生错位，例如原标题下划线是针对单行文本定位的，而新替换的标题折成了两行
- 图标对比度过低（例如深色底直接放深色图标，缺乏反差圆圈衬底）
- 文本框太窄导致单个词也频繁折行
- 残留的模板假字占位内容

## 转换为图片

将演示文稿转换为单张幻灯片图像以供视觉审查：

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

**直接将上面打印出的绝对路径传给图片查看工具（Read 工具）。** `rm` 会清理掉先前运行残留的旧图。`pdftoppm` 会根据总页数自动补零对齐文件名：10 页以内为 `slide-1.jpg`，10-99 页为 `slide-01.jpg`，100 页以上为 `slide-001.jpg`。

**修改代码后，必须重新运行上面的全部 4 条命令**：必须基于改好的 `.pptx` 重新生成 PDF，`pdftoppm` 才能反映你的最新改动。

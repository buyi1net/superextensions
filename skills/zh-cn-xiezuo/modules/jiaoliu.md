# 交流模块：把话说得让用户听得懂

> 管跟用户对话交流的可懂度：术语、深度、节奏。语气纪律（反讨好、反催促、表态方式）由各 agent 自己的交流规范管，不在本模块。写作产出物走 SKILL.md 主文件。

## 病根

模型跟用户说听不懂的话，和翻译腔是同一个病：产出者围着自己的知识结构组织语言（英文句法、术语习惯），而不是围着接收者的脑子组织语言。对用户来说，没解释的"心智模型"和没翻译的 mental model 一样难懂。**用户的认知就是目标语言**，交流的可懂度和翻译的意译是同一条纪律。

## 三连自问

每段回复写完，逐个过，不过不改不算完：

1. **这个词用户第一次见能懂吗？** 模型自然流出的术语（心智模型、范式、对齐、收敛）默认按"用户不懂"处理。
2. **不懂的我解释了吗？** 解释必须在首次使用之前或紧随其后，放在后面等于没解释。
3. **解释本身是人话吗？** 用类比和日常例子解释，不用另一个术语解释术语。

## 深度适配

动笔前先估用户对当前话题的水位，术语预算按水位定：

| 水位 | 判断依据 | 术语处理 |
|---|---|---|
| 在行 | 用户用行话提问、纠正过你的术语 | 直接用，点到为止别啰嗦 |
| 半行 | 用户懂领域但不懂这个角落 | 关键术语首现解释一次 |
| 外行 | 用户用生活语言提问 | 术语降级成人话，必须用的当场解释 |
| 拿不准 | 判断不了 | 偏讲清楚，看用户反应再收 |

## 术语降级表

高频模型黑话和人话对照。左边这些词对非技术用户换右边，或当场解释：

| 模型黑话 | 人话 |
|---|---|
| 心智模型 | 脑子里的图景 |
| 渐进披露 | 要用的时候才加载 |
| 范式 | 路数 |
| 对齐（认知义） | 统一认识 |
| 收敛 | 讨论稳定下来了 |
| 发散 | 把可能性都摆出来 |
| 抽象（动词） | 把共同点提出来 |
| 解耦 | 拆开，互不影响 |
| 优雅（代码） | 简洁好用 |
| 鲁棒 | 抗造、稳 |
| 上下文（对话义） | 前文、当前对话 |
| 复盘 | 回头总结 |
| 赋能 | 帮…做到 |
| 抓手 | 切入点 |
| 闭环 | 兜全了、一条龙 |

这张表是示例不是穷举。判定标准就一条：目标用户第一次读到能不能不假思索地懂，要猜的就换。

**表的生长规则**：用户问"这是什么意思"或表示听不懂时，说明表漏了这个词。在回复里报告"建议收录：词→人话写法"，由用户决定是否入库；用户明确同意后才写进本表（源稿在仓库里时），已安装插件副本一律只报告不改。这张表靠实际对话喂养，不是写完就死的。

## 节奏与格式

- **别过简**：不写电报体，不省到用户看不懂。"改 3 处，连带 2 处，已验"不行；"改了 3 个地方，受牵连的另外 2 处也一起改了，都验证过"才行。
- **列表只在内容真并行时用**：有先后顺序的内容用自然段讲，别把一句话拆成三个 bullet。
- **开场直接说结论**："值得注意的是""不难发现"这类引导语删掉。
- **删留按价值**：一句话去掉会不会变难懂或出错，都不会才删；不数字数、不设字数指标。代码、命令、路径、报错和涉及安全的步骤永远原样保留，删这些会出事。

> 堆砌反例：「本方案通过引入分层缓存机制，高效、稳定、可靠地全面提升了系统整体性能表现。」→「加了一层缓存，读操作变快，写入不受影响。」
>
> 过简反例：「改 3 处，连带 2 处，已验。」→「改了 3 个地方，受牵连的另外 2 处也一起改了，都验证过。」

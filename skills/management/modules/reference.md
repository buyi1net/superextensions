> 把项目使用的外部参考材料分类保存，让用户和 Agent 能从一个入口知道有哪些材料、为什么保留、在哪里、当前是什么状态，并能继续维护。

仅在首次建立参考场景、现有参考治理存在具体缺口，或用户明确要求整理、迁移和审计时使用本规范。已经能够自治的参考目录日常新增、拉取、更新和废弃直接执行项目内规则，不用本规范反复对照。

## 收录边界

放入参考材料目录：

- 外部收集，只用于理解、研究、比较、核验、举证、学习或借鉴的材料；
- 外部项目、制度、标准、文献、数据、模板、方法、素材、案例和样例；
- 正式输入或外部组成部分的说明、快照和分析记录，只承担参考或证据职责时也可以收录。

不放入参考材料目录：

- 项目正在产出或长期维护的自有成果、过程记录、正式数据、交付内容和运行内容；
- 当前工作需要直接采用、编辑、加工、执行或随成果交付的正式输入与外部组成部分。

识别参考材料看用途，不看目录名称，也不看用户是否说出“参考材料”。

## 正式输入和外部组成部分

当前工作需要直接采用、编辑、加工、执行或随成果交付的外部内容，按它在项目中的实际职责进入源码、运行内容或交付内容的对应边界，不得仅因来源在项目外就放入参考材料目录。相关说明、固定版本、快照和分析记录只承担参考或证据职责时，仍按参考材料管理。

无法确定外部内容是参考材料还是正式输入时，先保留现场并确认它在当前工作中的实际用途，不得先放入任意目录再补做归属判断。

## 解锁顺序

1. 先判断外部内容是参考材料还是正式输入，并确认来源、用途、生命周期和预期版本；不得以“先下载看看”“只是准备资料”为由跳过判断。
2. 首次使用参考目录时，依次完成以下入口：使用文件复制操作从[标准底稿](./templates/reference-agents.md)建立 `AGENTS.md`，建立固定的 `CLAUDE.md`，建立只描述当前实际状态的 `README.md`。重新读取三份文件并更新直接上级索引后，参考目录才解锁。
3. 参考目录尚无条目时，`README.md` 明确写当前无参考项，不预写计划分类、项目、链接或本地副本。
4. 新增参考项时，先确定分类并创建该项的说明文件，记录来源、价值、预期版本或快照、许可证或使用条件、生命周期和实际参考范围。说明文件完成前，不得向项目下载、复制或保存该项正文、仓库、网页、数据、素材或转换结果。
5. 只记录外部链接时，在说明文件完成后立即更新 `README.md`；需要长期本地副本时，先在说明中写明保存理由、目标位置和入库策略，再把内容直接取得到已确定位置。
6. 本地副本实际取得后，立即更新说明中的实际位置、固定版本、获取时间和更新方式，再更新 `README.md` 的当前状态。完成这两步前不得继续处理下一项参考材料。
7. 仅供本次核验且不长期入库的下载物进入已经解锁的项目临时区，不得先落入参考目录再删除，也不得仅因“一次性核验”使用系统临时目录。确实命中系统临时目录例外时，必须先向用户确认并记录准确路径、用途和清理目标。

禁止顺序：先创建分类空目录、先下载或拉取副本、先运行转换，再补 `README.md`、`AGENTS.md`、`CLAUDE.md` 或参考说明。最终文件齐全不能抵消此前顺序违规。

## 目录与分类

```text
<参考目录>/
├── README.md          # 人类阅读与查找入口
├── AGENTS.md          # Agent 维护入口
├── CLAUDE.md          # Claude Code 专用入口
└── <分类名称>/
    └── <参考项名>/
        ├── <说明文件>   # 如「参考说明.md」
        └── ...
```

**参考目录：**

- 作为项目一级目录，目录名称优先使用同级现有文件夹的语言和命名风格，哪怕同级文件夹是空的。
- 如果没有可参照内容，再按项目主要语言判断，不以当前对话语言判断。
- 后续可根据项目实际情况选择是否重命名为“参考资料”或者“reference”(比如用户要求整理资料的时候)。

**分类名称：**

- 分类名称使用用户在本项目中的主要交流语言。
- 已有分类时沿用现有语言，后续新增分类不得因单次对话语言变化而切换。
- 分类名称按材料在当前项目中的实际用途确定，例如核心依据、流程范例、竞品项目、视觉参考和其它参考；这些名称只是示例，不是固定目录。
- 同类材料使用同一分类；跨类材料按主要用途归类，次要用途写入参考说明。

**参考项名：**

- 每个参考项单独建立文件夹，名称优先使用来源原名，不翻译。
- 每个参考项都必须分类，只有一个参考项也不能直接散放在参考目录根部。

**其它事项：**

- 用不到的分类不创建，不预建空目录。
- 已有合理分类继续沿用。用户要求整理时可以按本规范重新分类；未获授权不得随意迁移或改名。

## 参考说明

每个参考项在取得本地副本前先建立一份说明文件，之后与本地存档放在同一个参考项文件夹中。说明文件不要命名为 `README.md`，避免与外部项目自带的 `README.md` 冲突；中文项目可用 `参考说明.md`。该文件不追求信息的大而全，只要求人类和其他 Agent 能快速看懂，同时避免撑满小窗口模型的上下文。

## README.md

`README.md` 是给人类阅读的统一入口，只写当前目录的实际内容和查找信息，不承担 Agent 操作手册职责，也不照抄本规范。文件开头应提醒 Agent 修改本目录前先读可点击的 `AGENTS.md` 链接，禁止无差别读取全部项目，避免占用上下文。

**基本要求：**

1. 当前实际分类及其用途(表格)；
2. 按分类排列的参考索引(固定写五行)。

```md
### <分类名称>

**项目：** <参考项名称>
**价值：** <用一句话说明这份材料为什么值得保留，以及它支持当前项目的哪项判断或工作>
**入口：** [参考说明](<分类名称>/<参考项名称>/参考说明.md) · [本地存档](<分类名称>/<参考项名称>/) · 版本或快照：`<固定版本或快照标识>`
**来源：** [<网站或来源名称>](<完整网址>) · 许可证或使用条件：<实际信息>
**时间：** 索引时间：<YYYY-MM-DD HH:mm>
```

**维护原则：**

- 实际分类列表使用可点击的相对文件夹链接。
- 没有本地存档时，在“入口”对应位置写“未获取副本”，不得创建不存在的链接。
- 来源没有网络地址时，使用来源名称和可复核的定位信息代替链接。
- 示例只定义索引格式；尖括号中的内容必须按实际材料替换，不得照抄为实际分类或内容。

## AGENTS.md

> `AGENTS.md` 是本目录给 Agent 使用的维护入口。只写当前目录长期有效的操作约束；
> 要做到即使 Agent 没有加载本规范，也应能仅凭该文件安全地整理和维护当前参考资料。

**维护原则：**

1. 新建 `AGENTS.md` 时，必须直接复制 [标准底稿](./templates/reference-agents.md)的完整内容作为起点，再根据项目调整各章节内容；不得先概括后重写，也不得凭记忆重建。
2. 已有 `AGENTS.md` 时，先判断空上下文 Agent 能否仅凭项目内入口安全完成新增、拉取、更新、废弃和验收；能够做到就保留原结构，不与标准底稿逐章比较。
3. 已有入口存在具体缺口时只补缺失能力。章节名称、顺序或写法与标准底稿不同，不单独构成缺口。
4. 只有用户明确要求迁移到标准制度时，才使用标准底稿重构已有入口；此时必须保留底稿全部 `##` 章节和顺序，并完整迁移项目专用约束。
5. 项目化调整完成后，项目 `AGENTS.md` 是本目录的直接维护入口；不得把本规范、外部 skill、本机缓存或前序会话作为能够继续维护的唯一依据。

## 本规范执行验收

本节由加载本规范并负责创建、修复或迁移项目入口的 Agent 执行。新建入口或用户明确要求迁移到标准制度时，必须重新读取[标准底稿](./templates/reference-agents.md)和最终 `AGENTS.md`，逐项对照实际章节；修复已有入口时只核对已经确认的具体缺口和自治能力，不得借验收机械改造其它章节。

1. `README.md`、`AGENTS.md`、`CLAUDE.md` 均已存在；`README.md` 和 `AGENTS.md` 能相互打开，`CLAUDE.md` 只含规定内容并能打开 `AGENTS.md`。
2. 新建入口或明确迁移到标准制度时，最终 `AGENTS.md` 保留标准底稿中的全部 `##` 章节和顺序；修复已有入口时保留原有有效结构和项目专用规则。
3. 确保 `README.md` 和 `AGENTS.md` 没有照抄本规范，也没有把一次性命令、工具或临时选择写成长期规则。
4. 根据操作记录确认参考目录三份入口早于分类和参考项，参考说明早于对应本地副本或链接入库，本地副本取得后立即完成了说明和 `README.md` 更新。
5. 新建入口或明确迁移到标准制度时，固定底稿通过实际文件复制建立，不是使用 `write`、记忆或整段生成重建；修复已有入口时有具体缺口依据，没有机械套用模板。

## 冲突处理

1. 用户明确要求优先；
2. 项目中明确记录为用户确认的专用规范其次；
3. 已有合理结构和统一风格继续沿用；
4. 没有更具体要求时执行本规范。

冲突无法判断时，先向用户确认。

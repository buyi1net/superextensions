# UI 文案与本地化资源

> 本模块处理 UI 字符串和本地化资源中的人类可读文本，只补这类载体相对于主框架新增的制度。RTL、字体、布局、locale negotiation 和运行时代码等完整 i18n 工程由项目开发规范负责。

本场景中，资源可解析和运行时语义正确优先于自然表达；意思与操作后果正确优先于产品语气和长度偏好。

## 进入前识别

动笔前查清目标 locale、资源格式和运行时框架、字符串出现位置、控件或交互状态、项目已有术语与同类文案。缺少界面语境时先查 key 的代码使用点；拿不准产品语气时抽查三个已有同类字符串。

## 共用技术约束

### 结构、转义和标记

资源格式、嵌套、数组、转义、标记和编码必须符合当前项目及运行时框架。不得为了自然表达破坏机器结构。不可翻内容按项目机制明确保护。

### key

- 翻译已有 locale 时，key 一律保持原样，不新增、不删除、不合并；发现源语言和目标语言 key 集合不一致时报告，不自行修补。
- 直接编写新的源语言 UI 字符串时可以新增 key，但必须遵守项目命名、资源登记和调用方式，不能套用“key 不得新增”的翻译规则。

### 占位符

- `{name}`、`%s`、`%1$s`、`{{count}}`、`%{count}` 等占位符的名称、数量、类型和格式说明逐字核对。
- 只有当前格式支持命名或位置参数时，才可按目标语言语序调整占位符位置；未编号的 `%s` 等顺序参数不得擅自重排。
- `{price:currency}`、`%.2f` 等格式说明符不许改写。数字、日期和货币显示应使用项目的 locale-aware 格式化能力，不在译文中硬编码另一套格式。

### 复数与选择分支

复数和 select 类别同时服从目标语言规则与当前运行时格式，不能机械照搬英语，也不能只凭中文语感删除分支。ICU MessageFormat 必须保留完整的 `other` 分支；扁平的 `key.one`、`key.other` 等结构按项目框架要求保持 key 集合，内容可以按目标语言规则相同。

框架惯例不明确时保留源结构并列为待复核，不自行选择精简策略。

### 界面语境和长度

- 按钮和菜单使用短而明确的动作名称，如“确定”“提交”“取消”“重试”；同一产品内同一动作使用同一译法。
- 错误消息要说明发生了什么和用户能做什么，同时跟随产品已有语气。
- 只有存在真实控件宽度、字符限制或设计要求时才缩写；缺少证据时报告截断风险，不默默删信息。
- 散字符串没有固定阅读顺序，不做“首次出现时中英并列”的术语标注。

## 任务分流

### 翻译已有字符串或 locale

额外完整读取并执行 [外文译中文](./fanyi.md) 或 [对外表达](./duiwai.md)，按实际语言方向选择一个。源文保真、key 一一对应、占位符和数字实体核对全部适用。

### 直接编写新的 UI 字符串

不执行“与源文一致”类翻译质检。根据产品意图、操作后果和当前界面状态写文案，检查脱离设计稿单独出现时是否仍不会误导用户；新增 key 按项目工程规则处理。

## 本地化质检

1. 先验证资源能被当前工具链解析，结构、key、转义、标记、复数分支和占位符符合选定策略；
2. 再检查意思、操作后果、术语、语气和长度；
3. 有可运行界面、预览或截图时放回真实界面检查；没有时明确说明未完成视觉验证；
4. 翻译分支额外执行所选语言方向模块的质检，直接编写分支不套源文保真项目。

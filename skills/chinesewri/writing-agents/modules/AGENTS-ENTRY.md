> 本模块管 `AGENTS.md` 入口文件和入口的层级规则:什么时候建,建在哪一层,写什么.`AGENTS.md` 里的文字怎么写,按[主 SKILL.md](../SKILL.md);`README.md` 怎么写,见 writing-style 的 [README 规则](../../writing-style/modules/readmes.md).是否需要在项目根或子目录建立入口,按「层级规则」的判定执行,不由执行 Agent 自行扩大或缩小.

## 核心原则

1. `AGENTS.md` 面向所有 Agent,是每一层的唯一 Agent 入口;任何 Agent 不得另行建立自己的入口源稿,各工具适配文件只从本入口派生;
2. 不新建 `CLAUDE.md`;已有的见「已有的 CLAUDE.md」;
3. 入口文件必须纳入项目版本控制,禁止加进忽略规则;入口的创建,修改,退役随同一次提交入库;
4. 防污染:`AGENTS.md` 不写面向人类的文档内容(那是 `README.md` 的职责);`README.md` 不写 Agent 操作步骤;
5. 防并行覆盖:修改入口前必须重新读取当前内容,只做精准追加或修改,禁止拿内存中的旧版本整体重写;发现内容被他人改过,先保住已有改动再动手.

## 装载时机

Agent 进入任何项目的第一个动作:查找并读取根目录 `AGENTS.md` 的开工顺序,然后才处理任务本身.

- 找不到入口的项目,按「层级规则」补建后再开工,理顺入口治理后再推进主体工作;只限本方自己的项目.在别人的仓库里(比如给开源项目提 PR),不补建入口,沿用对方已有的约定;
- 只读检查(浏览,诊断,验收)可以不建入口,但产生文件或外部副作用前必须先补.

## 层级规则

### 项目根

- 根 `AGENTS.md` 必有,用[根骨架](./templates/agents-root.md)创建;
- 根入口承担:项目概览,项目地图(全部一级目录的职责与入口),开工顺序,硬红线,维护规则路由.

### 一级目录

满足以下任一条件,才建立局部 `AGENTS.md`(用[子目录骨架](./templates/agents-dir.md)):

1. 该目录有场景规范可路由(如参考材料);
2. 该目录有自己特有的操作顺序或红线(如发布目录的版本转正);
3. 空上下文 Agent 会直接进入该目录干活,且做错会造成事故(如外部材料的「先说明后下载」).

不满足任何条件的目录:职责一行写进根入口的项目地图,不建局部文件.

**对外分发的目录除外：** 目录内容会被整体对外分发(交付树,发布目录,公开仓快照)时,不建随树分发的局部 `AGENTS.md`:该目录的研发侧维护规则(镜像同步,发布命令,变更联动)升入项目根入口维护;公开仓或交付树如需 `AGENTS.md`(服务自动化与贡献者),用 [public-agents.md](./templates/public-agents.md) 底稿单独写,作为交付内容随发布流程分发.

反向升级:目录从无到有,开始积累内容或出现特有规则时,触发条件出现,必须及时升级建立局部入口.

新增,移动或删除一级目录时,同一次提交更新根入口的项目地图;没有局部入口的目录,职责也要一行写进地图.

### 二级及更深目录

禁止建立任何入口文件;二级内容的说明用最近一级入口的相对链接覆盖.

## 冲突裁决

- 局部规则优先于根入口(更具体者优先),但不得违反根入口的硬红线;
- 根与局部规则存在冲突且无法判断时,保留现场并向用户请示,明确后再执行.

## 入口退役

目录主体内容清空或职责消失后,局部入口随之删除,根入口的项目地图同步更新,保持索引与实际目录一致.

## `AGENTS.md`

### 内容从哪里来

按顺序判断,命中即停:

| 当前情况 | 处理方式 |
|---|---|
| 用户已指定内容或结构 | 按用户要求处理 |
| 已有入口内容 | 保留原有结构;只修用户要求或已确认的具体缺口,不与标准底稿逐章比 |
| 新建且当前场景有标准底稿(如 reference-intake 的 [reference-agents.md](../../../productivity/reference-intake/templates/reference-agents.md)) | 文件复制底稿,再项目化精准修改;禁止凭记忆重建 |
| 新建根入口 | 复制[根骨架](./templates/agents-root.md) |
| 新建一级目录入口(无标准底稿) | 复制[子目录骨架](./templates/agents-dir.md) |

标准底稿是稀缺品,不预写,不求全:只收录经过实战验证的场景底稿.骨架创建的入口在实战中稳定后,由用户拍板固化为新的标准底稿.

### 内容边界

**写入：** 适用范围,项目边界,场景触发条件,命中后必须读取的稳定链接,读取专项规则前必须知道的最小红线.

**不写入：** 资料正文,工作记录,进度,临时待办,多步操作流程,命令参数,异常处理,面向人类的文档内容:这些进入职责归属的文件,由入口按条件路由.例外:一级目录的局部入口要让空上下文 Agent 仅凭它维护本目录,可以写本目录的操作顺序(比如参考目录的新增,拉取,废弃步骤).

### 读取纪律

`AGENTS.md` 及其路由到的文件中,所有链接都是按需加载语义,不是必读清单:按当前任务需要选读,禁止见到链接就全量读取.小窗口模型尤其注意:上下文预算优先留给任务本身,导航类内容读到能定位目标即停.

## 已有的 CLAUDE.md

Claude Code v2.1.277 起,目录里没有 `CLAUDE.md` 时会直接读 `AGENTS.md`,所以不新建 `CLAUDE.md`.但当前目录或任一上级目录里只要有 `CLAUDE.md`,`.claude/CLAUDE.md` 或 `CLAUDE.local.md`,Claude Code 默认就只读它们,不再读 `AGENTS.md`.出处:[Claude Code 官方文档](https://code.claude.com/docs/en/memory)的 AGENTS.md 一节.

遇到已有的这类文件:

1. 禁止擅自删除.
2. 本方项目里,内容只是转发到 `AGENTS.md` 的,改成一行 `@AGENTS.md` 导入,让 Claude Code 稳定读到入口;带独有规则的,先把独有内容迁入同级 `AGENTS.md`,确认无遗漏后再改成导入.
3. 别人的仓库里,保持原样.

其它工具的专属入口同样只做转发到 `AGENTS.md` 的适配层,不预建,不写规则正文.

## 验收

**项目根：**

1. 根 `AGENTS.md` 存在且项目地图与磁盘一致:地图里的每个目录都实际存在,磁盘上的一级目录都在地图里(第三方工具生成的目录除外,比如 `node_modules/`,`target/`);
2. 地图和路由里的链接可打开;硬红线不与场景规范冲突;
3. 入口文件已纳入版本控制.

**一级目录：**

1. 建有局部入口的目录,准入条件至少成立一条;没有局部入口的目录,职责已在根地图登记;
2. 局部入口能让空上下文 Agent 仅凭它完成本目录的日常操作(判断边界,找到规则,执行顺序,知道红线).

**通用：**

1. 新建或大幅修改入口后,以「第一次进入本项目」的视角通读:仅凭入口能回答「这是什么项目 / 当前任务该读什么 / 什么不能碰」;
2. 入口退役的目录没有残留地图条目或孤儿文件;
3. 变更联动:本次新增,移除或变更的内容,登记它的所有位置(各级 README 索引,路由,对外清单)已在同一次提交里同步.

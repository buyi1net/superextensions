---

任何中文成稿(文档,报告,commit,skill 正文,规则)交稿前必须过检.本检查只管当前交稿,交稿后的对话和其它产出不受它约束.

## 审查准备与输入

开始质检前,先明确三项输入:

1. **原始依据**:本次写作的需求,spec,工单,设计记录或原文.依据用来判断内容是否漏项,擅增或失真.
2. **目标成稿**:完整的待交付正文,不只看局部片段.
3. **目标载体**:确定文档面向读者,并加载对应标准:
   - 给人读的文档:加载 [writing-style](../writing-style/SKILL.md).
   - 给 Agent 读的文档:加载 [writing-style](../writing-style/SKILL.md) 与 [writing-agents](../writing-agents/SKILL.md).
   - skill 正文:额外按 [SKILL-MECHANICS](../writing-agents/modules/SKILL-MECHANICS.md) 核对适用的各项:目录与元数据,调用方式,拆分和路由;用不上的项注明不适用.

## 质检流程

按改动规模执行检查:

- **新写或大改**(动了结构,加了新概念):
  1. 执行机械检查(必过项).
  2. 执行双线审查:内容保真线与文风语感线.
  3. 执行视角检查.
  4. 改动后按复查闭环重扫.
  5. 按冷读终审标准判定并执行冷读.
- **小改**(修措辞,局部替换,删冗余):
  1. 自查机械检查与本次改动触及的审查维度,至少自查陌生读者视角.
  2. 改完复查一遍对应项即可,免去完整冷读.

## 机械检查(必过)

- **破折号一律清理**:全文搜「——」和「—」,一处不留.引出解释用冒号,补充说明用括号,前后两个意思拆成两句.
- **超过 150 汉字的段落逐段检查**:装了两件以上的事情,就拆成多段;围绕单一论点完整阐述的一件事,可以保留.
  - 计数口径:普通段落,列表项,引用块里的每个自然段各算各的;代码块和表格单元格不算.
- **行内并列改列表**:段落内出现「第一...第二...」,或一句话串起三条以上并列规则与步骤,改为列表排版.

## 双线审查

内容保真与文风语感分两条线检查,分开写报告.自查时「独立」是指分开检查,分开记录问题,不要求必须换不同的人.文风语感线只提语言问题,不能借口口气删改实质规则;内容保真线只查事实与逻辑,不因文风通顺掩盖失真.

### 第一线:内容保真审查

对照原始依据,逐项核对四类问题:

1. **漏掉**:原始依据中的前置条件,核心逻辑,技术限制,依赖关系或失败分支是否被遗漏.
2. **擅自增加**:成稿中是否出现未经授权的假设,新机制,额外步骤或未承诺的完成时间.
3. **力度改变**:事实的确定性或规则的约束力度是否失真.详见下方「力度保真对照表」.
4. **受保护内容与实现核验**:对照 [writing-style 的受保护内容分类](../writing-style/SKILL.md),逐项检查字面保护类对象有没有被破坏(必须一字不改),检查语义保护类对象的内容与力度有没有保住(措辞改写或翻译不得改变原义),并核验文中的配置键,路径,命令,示例与文件引用是否真实可访问.

#### 力度保真对照表

| 原始语义 | 合格转述 | 失真反例(禁止) |
|---|---|---|
| 推测 / 怀疑 | 可能是,推测为,尚待核实 | 确认是,事实证明,坐实 |
| 建议 / 推荐 | 建议,推荐,可考虑 | 必须,绝对,一律要求 |
| 计划 / 规划 | 计划排查,拟在后续处理 | 当日修好,保证完成,承诺交付 |
| 暂缓 / 搁置 | 暂时搁置,延后评估 | 永久拒绝,不予支持,永不修复 |
| 承诺 / 硬约束 | 必须,绝对,严格保证 | 建议尽量,视情况而定(擅自弱化) |
| 明确拒绝 | 不支持,禁止,无法实现 | 暂未决定,可以考虑(擅自放宽) |

### 第二线:文风与语感审查

对照 [writing-style](../writing-style/SKILL.md) 审查语言质感,查找套话,官腔,训诫味与翻译腔.受保护内容清单按 `writing-style` 执行,不作误报.

#### 套话与病灶排查

普通修饰语按下列方式处理;属于术语或项目固定用法时保留(如「闭环」「回归测试」):

- 「值得注意的是」「不难发现」「我们可以看出」「正如我们所知」:删掉,直接陈述结论.
- 「为了更好地」「在...的基础上」「对...进行(分析/处理)」:改用直接动词.
- 「标志着」「见证了」「奠定了」:删掉主观评判,保留可核验事实.
- 「赋能」「抓手」「深耕」「沉淀」「矩阵」「生态」「赛道」「闭环」:普通修饰时换成具体工程动作.
- 「不仅...更是...」「既...又...还...」:无实质对比意义时拆句.
- 「蓬勃发展」「日新月异」「举足轻重」「不可或缺」:替换为客观数据或事实.
- 「展望未来」「机遇与挑战并存」「前景广阔」:有具体下一步就写,没有就结束.
- 三连排比:按实际项数写,不硬凑三项.
- 副词加形容词堆砌(如「全面提升了整体性能表现」):删去修饰,留具体事实(如「读操作变快,写入不受影响」).
- 连续被动句(「被...」「得到了...」):能用主动句就用主动句,但不要为了改成主动句去补造一个不存在的施事者.
- 一句含多个限定词:删去多余修饰,一句话讲一个重点.
- Agent 指令里误带聊天称呼:检查是否混入口头称谓;给人看的文档和界面文案里正常使用称呼的,不算.
- 连续法务式禁令(如一串连着的「不得」「严禁」「违者」):改为清楚的条件与动作.改成正面写法时,原有硬约束不能降级.
- 训诫与审视语气:居高临下的说教改为平视交代事实,依据和动作.
- 残缺短句与电报体:补齐必要成分,写完整句子.
- 机械客服腔:换成平实自然的工程师动作词.

#### 翻译腔排查(原创中文亦适用)

- **代词悬空**:「它/他」缺少前置先行词,补齐先行词或重复名词全称.
- **隐性被动**:「功能已由模块 A 跑通」改为主动句「模块 A 已经跑通功能」.
- **抽象名词悬空**:抽象状态词落到具体场景,如「整体切换(更换服务商或数据库)」.
- **动宾残缺**:「点击并复制」补齐为「点击对应按钮并复制该路径」.
- **俏皮表演腔**:俏皮词连排,处处抖机灵,改用平实自然的工程师口吻.
- **长句定语过重**:前置定语超过两层,或者长句没拆,当作重读的信号;确认确实影响理解,再拆成流水短句或改话题句.
- **名词化堆叠**:「对接口调用的执行」还原为动词句「调用接口」.
- **连接词堆叠**:因果或条件已靠语序自然显现时,省去多余连接词.
- **泛指量词滥用**:泛指事物不加「一个」,如「新建一个文件」改为「新建文件」.
- **结论缺乏依据**:只有断言却没有前置依据或后续影响,补齐因果逻辑.

对照「骨架是否重组、意思是否保真」的具体反例与合格改写,见参考模块 [`STRUCTURE-EXAMPLES.md`](./modules/STRUCTURE-EXAMPLES.md).

## 视角检查

交稿前切换三个视角通读:

- **陌生读者视角**:读者只具备自己环境里本来就有的东西(项目总纲,同一个插件里的其它 skill,通用常识),不带本次会话背景.检查是否存在未解释的暗语或悬空指代.
- **环境视角**:
  - 给 Agent 的文档:同包内容(skill 名,模块名)可以互引;项目路径只能出现在项目级文档,分发出去的 skill 不写「本仓库」这类项目自称;环境设施仅作举例说明,不把特定本机环境写成普适事实.
  - 给人的文档:公开发布指引不得依赖内网地址或个人本机私有绝对路径.
- **人类视角**:检查自造词是否当场给出权威定义,长文结构是否便于快速扫视定位.

## 质检报告格式

审查完成后,按以下格式分开写报告:

```text
## 质检报告: [文档名]

### 一、内容保真审查
- [通过 / 发现问题]
- 问题项: <位置 file:line> | <类型: 漏项/擅增/力度改变/引用无效> | <问题说明与修改建议>

### 二、文风语感审查
- [通过 / 发现问题]
- 问题项: <位置 file:line> | <类型: 机械项/套话/翻译腔/段落过长> | <问题说明与修改建议>

### 三、视角检查
- [通过 / 发现问题] (小改若只查部分视角,写明实际检查了哪些)
- 问题项: <位置 file:line> | <检查维度: 陌生读者视角 / 环境视角 / 人类视角> | <问题说明与修改建议>
```

## 复查闭环

改稿后必须复查一遍,防止引入新问题:

- **小改**(修改局部词句):对改动波及维度全文重扫,新写句子必须重过机械检查与套话与病灶排查.
- **大改**(重构段落或改动逻辑):全套检查(机械检查,双线审查,视角检查)重新执行一遍.

## 冷读终审

### 冷读门槛

按传播风险决定是否执行冷读:

- **必须冷读**:进入公开交付仓,对外发布,或长期供所有 Agent 读取的正文,只要属于新写或大改,必须通过冷读.
- **免冷读**:本地一次性草稿,临时会话记录,在完成自查后可免去冷读.
- **拿不准**:一律按高风险处理,执行冷读.

### 冷读执行规范

- **隔离输入**:派独立的子代理担任冷读者.只提供成稿和读者真实可得的参考材料(陌生读者视角),禁止提供写作历史,设计会话或修改背景.内容保真审查才看原始依据.
- **提问方向**:要求冷读者指出哪些地方读不懂,哪些引用不清晰,哪些句子读着卡壳或具有翻译腔.
- **冷读者只挑毛病**:冷读者只挑毛病,不修改稿件.作者逐条评估反馈,落实修改或说明误报理由.
- **复读机制**:小范围调整自查即可;涉及整段重写的部分,需由冷读者再读一轮.
- **冷读兜底**:没有子代理可用,就开一个不带历史记录的新会话来读;两样都没有,才在交稿时标明「未经冷读」,请用户抽查.

# 文件路径

> 本模块只处理已经由主 skill 选择的文件路径,不重新判断交付方式,也不执行消息路径.

## 确定保存位置

如果用户明确指定了保存目录或文件路径,直接按用户的要求保存.如果没有指定,按下面的顺序确认项目根目录:

1. 优先使用当前环境直接提供的 workspace 根目录,并确认里面的 `AGENTS.md` 确实是项目根入口.
2. 如果环境没有提供 workspace 根目录,从当前工作目录逐级向上查找 `AGENTS.md`.结合版本库根目录和文件内容,区分清楚项目根入口、局部入口和转发文件,不要单纯抓到第一个同名文件就当成项目根.
3. 磁盘根目录、文件系统根目录、操作系统目录、用户个人主目录以及系统临时目录,都不能当成项目根.
4. 如果无法可靠确认项目根目录,直接停下来向用户询问保存到哪里,不要瞎猜,也不要把文件随手甩到系统临时目录里.

确认好项目根目录后:

1. 在项目根目录下创建或复用 `.agents/handoff/` 文件夹.
2. 文件名统一使用 `handoff-<YYYYMMDD-HHMMSS>.md`,时间取当前本机时间.
3. 写入前检查是否重名;如果遇到重名,在末尾追加短随机后缀(例如 `handoff-20250120-143052-a3f9.md`).
4. 绝对不要覆盖已经存在的文件.

## 保存前自查

文件交付生成的是用户需要长期留存的正式交接文档,保存前顺手通读一遍:
核对文档里是否完整交代了用户的目标、关键约束、真实进展、关键技术决策、下一步具体动作以及相关代码的位置.如果发现有遗漏的信息,或者还有没验证过的推测,老老实实交代清楚来源再保存.

## 回复规范

文件写入成功后,直接输出交接文档在机器上的真实绝对路径.除非用户明确要求查看全文,不要把整篇正文贴到聊天窗口里刷屏.

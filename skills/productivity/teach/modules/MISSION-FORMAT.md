# MISSION.md 格式

`MISSION.md` 放在工作区根目录下，记录学生学这个话题的**根本原因**。每一个教学决策，接下来教什么、推荐哪些资源、设计什么练习，都要能追溯到这份文件。

## 模板

```md
# 学习目标：{话题}

## 为什么学
{用一到三句话说明。学生追求的具体现实目标是什么？掌握这个技能后，他的生活或工作会发生什么变化？避免「为了理解 X」这类空泛的说法，要挖出背后的真实诉求。}

## 成功的模样
- {学生能做出的某个具体、可观察的表现}
- {另一个具体表现}
- {……}

## 约束条件
- {时间、预算、已有安排、学习偏好，以及任何会限制教学方式的因素}

## 暂不涉及
- {学生明确表示目前不想碰的周边话题，用来守住最近发展区的边界}
```

## 规则

- **一个工作区只放一个目标。** 如果学生想学两件互不相干的事，那就开两个工作区。
- **要具体，不要空泛。** 「十月份跑完半马」比「把身体练好」强，「用 Rust 给团队写一个命令行工具」比「学 Rust」强。
- **遇到含糊的就说出来。** 如果学生自己也说不清为什么想学，就先别急着写，多问几句。目标定歪了，比没目标还糟。
- **目标变了就改。** 学习目标会变。学生的方向调整了，就及时更新这份文件，别让过时的目标带偏后续的课程。
- **保持简短。** 如果 `MISSION.md` 长到一屏装不下，那它就失去了指引方向的作用，变成一张计划表了。

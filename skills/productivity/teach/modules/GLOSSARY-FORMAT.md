# GLOSSARY.md 格式

`GLOSSARY.md` 是这个教学工作区的标准用词手册。所有的讲解、练习和学习记录，都要遵照它的术语来写。建词汇表本身就是学习的一部分，能把一个概念压缩成一句精准的定义，本身就说明学生真正理解了。

> 这份词汇表管教学语言；项目领域模型的 `GLOSSARY.md` 归 `domain-modeling` 管，两回事。教学工作区独立成目录，互不打架。

## 结构

```md
# {话题} 词汇表

{用一两句话说明这个词汇表覆盖的话题范围。}

## 术语

**变量**：
用来存放数据的容器，每个变量有名字和对应的值。
_避用_：存储位、数据盒

**函数**：
把一段反复用到的逻辑打包起来，起个名字，随时调用。
_避用_：方法、子程序（在入门阶段先用「函数」统一口径）

**循环**：
让同一段代码反复执行，直到满足某个条件才停下来。
_避用_：重复执行、轮转
```

## 规则

- **只有学生真正理解了的术语才加进来。** 词汇表是压缩知识的记录，不是给学生预习用的字典。如果一个概念刚介绍完，先等一等，等学生能正确运用了再收进来。
- **要有主见。** 同一个概念有好几个说法时，选最贴切的那个，把其他的列为「避用」。这样才能真正压缩语言。
- **定义要精炼。** 一两句话就够了。定义这个词「是什么」，而不是「有什么用」或「怎么做」。
- **定义里优先用词汇表已有的术语。** 一个词一旦进了词汇表，后面所有地方都用它，包括在其他术语的定义里。这样复杂概念后面才好理解。
- **自然归类时加小标题。** 当某些术语明显属于同一类时（比如 `## 解剖学`、`## 编程概念`），就归在一起。如果所有术语本身就很统一，平铺也行。
- **有歧义就明确说明。** 有时同一个词在市面上用得很乱，不同的人有不同的用法。为了避免学生学的时候被搞糊涂，你在词汇表里要自己定一个规矩，在这个教学工作区里，这个词就按这个意思来用，其他的用法统统不算。比如：本工作区中，「函数」一律指有返回值的代码块；不返回值的叫「过程」，不混着叫。
- **理解深化了就要改。** 学生第一周写的定义，到了第六周可能就不够准确了。直接在原处更新就好，不用留着旧版本。

本 skill 只回答一件事:文件和目录该放哪.移动,重命名,删除和清理时,本 skill 只检查归属;操作要不要先确认按总纲执行,什么时候删听用户的安排.

## 已有约定优先

项目已有的结构和命名一律沿用,新增同类内容也放进已有的落点.用户明确要求整理时才调整已有结构,不得为了对齐下面的速查表擅自改名或搬迁.

已有约定的例子:源码在 `lib/`,测试在 `test/`,交付根叫 `build/`,多包项目的 `packages/*/src/`,Tauri 的 `src-tauri/`,Go 的 `cmd/` 和 `internal/`.

新项目先遵循语言,框架和构建工具的目录约定,框架没规定的部分再用速查表.

## 常用目录速查表

表里的目录名是没有既有约定时的默认落点,不是必须建齐的清单.表里都是开发类目录;非开发项目没有通用默认,按规则 4 和规则 7 处理.

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `src/` | 源码.内部怎么组织,用 Skill 工具加载 `codebase-design` | 一次性脚本,临时运行产物 |
| `tests/` | 项目集中存放的测试和测试数据;单元测试放哪按语言和测试工具的惯例定,适合跟着被测代码的就跟着放 | 本次运行产生的临时日志,截图和报告 |
| `scripts/` | 要反复执行的项目脚本,比如构建,校验,同步 | 一次性脚本,放 `temp/` |
| `docs/` | 要长期保留的说明,架构,决策,计划 | 只服务当前工作的临时报告,放 `temp/` |
| `reference/` | 外部项目和资料的本地副本;收录时用 Skill 工具加载 `reference-intake` | 项目自己的内容 |
| `temp/` | 临时文件和一次性工作文件,比如一次性脚本,运行日志,截图 | 要长期保留的内容 |
| `delivery/` | 发布产物,按项目自己的发布流程放 | 开发中的半成品 |
| `archive/` | 退出当前流程,还要追溯的旧版本和旧方案 | 当前还在用的内容 |

## 规则

1. **落点红线.** 禁止把 Agent 自己的产物写到项目外;确实要放项目外,先问用户.命令中由 Agent 指定的输出目标同样受这条红线约束,比如下载目录,日志,报告,以及 `git worktree add` 的目标路径.
   - 项目根是当前所在 git 工作树的根;不是 git 仓库时,是当前工作目录.进入嵌套的外部仓库(比如 `reference/` 下的参考项目)干活时,项目根仍是被维护的那个项目.
   - 当前目录是家目录,盘符根这类宽泛位置时,先问用户项目在哪.
   - 要新建一个独立项目时,用户没指定位置就先问,不建在当前项目里面.
2. **目录跟着内容走.** 有内容要放了才建目录,不预建空目录.
3. **层级尽量浅.** 文件有明确的所属目录就放进去.能不放根目录就不放,能不多建一级目录就不多建,非建不可时照建.项目入口,构建清单和工具链规定放在根目录的文件照常放根目录,比如 `README.md`,`Cargo.toml`,`package.json`.
4. **清单外的一级目录按职责判断.** 先看同类内容有没有现成落点,有就沿用.确有独立职责,又不会给同一类内容再建一套落点的,直接建;拿不准时问用户.不同包各自的源码和测试目录不算重复.`utils2/`,`new_docs/` 这类和已有目录职责相同的,不建.
5. **命名.** 一级目录用英文.二级及以下的目录和文件名,能用母语就尽量用母语;代码,工具链,脚本要求英文的用英文,比如源码模块,包名,脚本文件.已有的命名照旧沿用.
6. **不复制文件留旧版本.** 禁止复制文件改名留底,比如 `_old`,`_bak`,`_v2`,`副本`,`.bak` 这类.旧版本靠 git 的提交历史查;要长期留着追溯的,放 `archive/`.
7. **归属不明就问.** 先看项目已有约定和相关 skill;还找不到明确归属,就问用户放哪,不要自己先找个地方放着.
8. **在别人的仓库里.** 临时文件沿用对方已有的临时目录约定.没有约定时用 `temp/`,并把它加进 git 的本地排除文件;路径通过 `git rev-parse --git-path info/exclude` 获取,worktree 里的 `.git` 是文件,不要手写 `.git/info/exclude`.不是 git 仓库就不加.禁止为此改对方的 `.gitignore`.

## 本 skill 不管的事

下面这些不归本 skill 管.不管不等于不能改,修改时照常遵守其它规则.

- 第三方工具创建或规定的目录,比如 `.github/`,`node_modules/`,`target/`,`src-tauri/`:按工具自己的约定处理,本 skill 不重新分类或改名.
- 工具自动写进系统临时目录的文件.Agent 主动把输出指定到项目外的,仍按规则 1.
- 其它 skill 明确规定了目录和生命周期的:内部怎么组织,什么时候建,什么时候删,按那个 skill.
- 规格书和工单放哪,临时文件什么时候删.
- 新建,移动或删除一级目录后,在根 `AGENTS.md` 的项目地图和 `README.md` 的目录索引里同步登记;怎么登记,见 writing-agents 的 [入口规则](../../chinesewri/writing-agents/modules/AGENTS-ENTRY.md) 和 writing-style 的 [README 规则](../../chinesewri/writing-style/modules/readmes.md).

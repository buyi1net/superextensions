# 工作交接

> 把当前会话压缩成一次性交接文件：人能快速审阅，下一位 Agent 能在看不到原对话的情况下继续工作。只生成交接文件，不回答原问题，也不继续执行原任务。

## 信息纪律

- 只整理当前可见上下文；除确定保存位置外，不要新调查、改代码、跑测试、提交或访问外部系统。
- 用户传入的参数代表下一位接手者的关注点，据此调整内容详略，但不得因此漏掉继续工作必需的信息。
- 只存在于会话中的目标、约束、决定、状态、失败原因和待办必须写入。
- 已有 PRD、计划、ADR、issue、commit、diff 等产物只说明其作用并引用路径或 URL，不重复抄写正文。
- 不确定的信息标为“未确认”；不要编造路径、URL、issue、commit、命令结果或测试结果。
- 隐去 API key、密码、token、私钥、完整 `.env` 内容和与接手无关的个人身份信息。
- 继续工作必需的文件路径、符号名、命令、错误原文、URL 和 commit hash 必须精确保留。
- 使用简体中文；代码、命令、路径、错误信息和必要的技术标识保持原文。

## 必须覆盖的信息

交接文件不是固定表格。根据当前任务自由组织内容，但有内容时不得遗漏以下信息：

- 用户接下来要完成什么，以及用户明确提出的偏好、限制和授权边界。
- 已完成且经过验证的工作、当前正在进行的工作、尚未开始的工作和真正阻止继续推进的问题。
- 已确认的决策及原因、仍未确认的假设与风险、继续工作必须知道的历史取舍和并行工作。
- 下一位 Agent 可以立即执行的具体动作。
- 相关文件、符号、命令、错误、URL、commit 和其它已有产物的位置及作用。
- 下一位 Agent 应加载的 skill。将其单独放在“建议加载的 skill”章节，只列当前环境中已确认存在且后续确实需要的 skill，不猜测名称，也不要列出 handoff skill 本身。

重要内容无法归入现有章节时，新增合适的章节，不要为了套模板而丢掉信息。

## 组织方式

- 章节名称、顺序和层级可以按任务调整；相关内容可以合并，没有内容的章节可以省略。
- 优先使用便于扫描的短句和列表；存在因果关系、取舍过程或复杂上下文时，用完整段落讲清楚，不强行拆成列表。
- 不要在文件中描述交接过程本身，例如“以下是摘要”或“我将上下文整理如下”，直接呈现交接内容。
- 文件末尾原样保留“接手确认”章节；这是接手流程，不得省略、合并或改写。

可以从下面的结构起步，但不得把它当作字段齐全、顺序固定的表单：

<handoff-template>

## 当前状态

### 已完成

### 进行中

### 待办与阻塞

## 决策与重要上下文

## 下一步

## 相关文件与命令

## 建议加载的 skill

## 接手确认

读取并理解本文件后，先不要执行任务：

1. 主动删除本文件。
2. 用自己的话向用户复述目标、当前状态、关键约束和准备采取的第一步。
3. 明确说明本文件是否已经删除；没有删除时说明原因。
4. 询问用户是否还有补充或修正，收到回复后再按用户的最新意图开展工作。

</handoff-template>

## 处理已有摘要

- 如有 `<prior-summary>` 或 `<previous-summary>`（上一份交接快照或压缩摘要），将仍然有效的内容与当前对话合并，生成不依赖旧摘要的自包含新快照。
- 对话未提及但继续工作仍需要的目标、约束、用户指令、决策和并行工作原样带入；只丢弃已经完成且后续不再需要的内容。
- 当前对话比旧摘要新；两者冲突时以当前对话为准，写入修正后的事实并删掉旧说法。
- 补充当前对话中的新进度、决策、约束和上下文；已完成、进行中、待办和阻塞必须反映当前真实状态。
- 阻塞解除后更新状态，但保留继续工作仍需要的失败原因和解决结果。
- 不要把 `<prior-summary>`、`<previous-summary>` 或 `<handoff-template>` 标签写入最终文件。

## 保存

用户明确指定保存目录时，以用户指定为准。否则按以下顺序确定项目根：

1. 优先使用当前环境明确提供的 workspace root，并确认其中的 `AGENTS.md` 是项目根入口。
2. 环境没有提供 workspace root 时，从当前工作目录向上查找 `AGENTS.md`；结合版本库根和入口内容，区分项目根入口、局部入口和适配转发文件，不要简单采用最近的同名文件。
3. 磁盘根、文件系统根、操作系统目录、用户主目录和系统临时目录不算项目根。
4. 无法可靠识别项目根时，询问用户将文件保存到哪里；不得猜测，也不得退回系统临时目录。

确认项目根后：

1. 在项目根创建或复用 `.agents/handoff/`。
2. 文件名使用 `handoff-<YYYYMMDD-HHMMSS>.md`，时间取本机当前时间。
3. 写入前检查重名；冲突时追加短随机后缀，例如 `handoff-20250120-143052-a3f9.md`。
4. 不覆盖已有文件。

## 保存前自查

把交接文件当作唯一可见上下文通读一遍：下一位 Agent 能否说清用户目标、当前真实状态、关键约束、准确下一步和材料位置。缺一项就补齐；发现无依据的事实、失效引用或敏感信息，先修正再保存。

## 回复

保存完成后，只输出交接文件在本机的真实绝对路径，不加说明文字：

```text
<absolute-path-to-project>/.agents/handoff/handoff-<YYYYMMDD-HHMMSS>.md
```

除非用户明确要求预览，不要把交接正文贴到聊天里。

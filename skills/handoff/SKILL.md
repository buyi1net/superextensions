# 工作交接

> 把当前会话整理成**交接快照**:人能快速审阅,下一位 agent 能直接接手。不需要完全遵循下面模板的固定字段，目标是让下一个agent可以完整接手你当前工作而不丢失重要上下文。

## 信息纪律

- 只整理可见上下文;不要新调查、改代码、跑测试、提交或访问外部系统。
- 用户传入参数 = 下一位接手者的关注点。
- 不确定就标"未确认";不要编造路径、URL、issue、commit、命令结果或测试结果。
- 已有 PRD、计划、ADR、issue、commit、diff 中记录过的内容,只引用路径或 URL。
- 不泄露 secrets、token、私钥、完整 `.env` 内容。

## 输出纪律

- 严格按模板输出,每个小节都保留,为空也写"(无)",不改顺序。
- 用短句列表,不写成段落。
- 精确保留文件路径、符号名、命令、错误原文、URL、commit hash;已知才写。
- 使用简体中文;代码、命令、路径、错误信息保持原文。
- 不要在快照里描述交接过程本身(如"以下是摘要""我将上下文整理如下"),直接呈现内容。

## 处理已有摘要

- 如有 `<prior-summary>` 或 `<previous-summary>`(上一份交接快照或压缩摘要),按下方合并规则生成自包含的新快照;新快照不得依赖旧摘要补充信息。
- 不要把 `<prior-summary>`、`<previous-summary>`、`<handoff-template>` 标签写入最终文件。

### 合并规则

- 对话未提及但仍有用的目标、约束、用户指令、决策、并行工作流,原样带入;只丢弃已完成且继续工作不再需要的内容。
- 对话比旧摘要新:两者冲突时以对话为准,写修正后的事实,删掉旧说法。
- 从对话补充新的进度、决策、约束和上下文。
- 已完成的工作从"进行中"移到"已完成"。
- 尚未开始且不构成阻塞的工作归入"待办",不要混入"进行中"或"阻塞"。
- 阻塞已解除就更新状态,但保留继续工作仍需要的细节。
- "目标"和"下一步"必须反映当前真实状态,不照抄旧摘要。

## 模板

<handoff-template>

# 交接快照

## 目标
- [一到两句:用户接下来要完成什么]

## 用户意图与约束
- [目标、偏好、限制和用户明确指令;没有则写"(无)"]

## 工作状态

### 已完成
- [已完成的工作、已验证的事实、已做出的变更;没有则写"(无)"]

### 进行中
- [当前正在推进但尚未完成的工作;没有则写"(无)"]

### 待办
- [尚未开始或仍待处理、待验证的工作;没有则写"(无)"]

### 阻塞
- [确实阻止继续推进的问题、失败的命令及原因;没有则写"(无)"]

## 决策与原因
- [已确认的决策:做出该决策的原因;没有则写"(无)"]

## 重要上下文
- [继续工作必须知道的背景、边界、错误、历史取舍和并行工作流;没有则写"(无)"]

## 风险与待确认
- [风险、假设、未知项和需要用户确认的事项;没有则写"(无)"]

## 下一步
1. [立即执行的具体动作;没有则写"(无)"]
2. [已知则写后续动作;没有则省略此行]

## 相关文件与命令
- [路径或命令:为什么重要,结果已有则注明;没有则写"(无)"]

## 接手注意事项
- [优先读什么、避免什么、建议使用哪些已知 skill;没有则写"(无)"]

## 给 Agent

该文件为一次性交接文件， Agent 接手工作后，请主动删除该文件。

</handoff-template>

## 保存

用户明确指定保存目录时,以用户指定为准;否则按以下优先级确定保存位置:

1. 当前工作目录下已存在 `.agents` 目录 → 在其中创建 `handoff` 子目录(已存在则复用),保存到 `<当前项目>/.agents/handoff/`。
2. 当前工作目录下没有 `.agents` 目录 → 保存到系统临时目录,例如 `$TMPDIR`、`TEMP` 或 `TMP` 指向的位置。

**注意事项:**

1. 不要为了保存交接文件新建 `.agents` 目录,只允许在其下新建 `handoff` 子目录。
2. 文件名:`handoff-<YYYYMMDD-HHMMSS>.md`。
3. 写入前检查重名;冲突时追加短随机后缀,例如 `handoff-20250120-143052-a3f9.md`。
4. 不覆盖已有文件。

## 回复

保存完成后,只输出真实绝对路径:

```text
Handoff saved to: /absolute/path/to/handoff-<文件名>.md
```

除非用户明确要求预览,不要把交接正文贴到聊天里。
